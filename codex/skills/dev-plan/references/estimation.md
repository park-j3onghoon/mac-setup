# dev-plan 정량 일정 산정 레퍼런스

`dev-plan`의 일정 산정 단계에서 적용하는 승수·산출 근거·출력 템플릿.

## 일정 산정 철학 (CRITICAL)

> **일정은 낙관적으로 잡지 않는다.** 변수와 리스크를 충분히 반영한 현실적 산정을 기본으로 한다. 조기 완료 시 다음 작업을 앞당겨 진행한다.

## 2. AI 에이전트 기반 작업 시간 산정 (CRITICAL)

사람의 역할은 **지시(prompting) + 전체 코드 리뷰**. AI가 빠르게 생성해도 **코드를 읽고 이해하는 시간**은 코드량에 비례하여 줄지 않으며, AI 오생성 디버깅/재지시(체감 20~30%)도 포함한다. 승수는 **보수적**으로 잡는다("빨리 끝남" > "일정 밀림").

### 작업 유형별 AI 시간 승수 (전통적 수동 코딩 대비)

| 작업 유형 | 승수 | 시간 구성 비율 | 예시 |
|-----------|------|---------------|------|
| **고가속** (반복적, 패턴 기반) | **0.4~0.5x** | 지시 10% + AI 생성 대기 5% + 리뷰/이해 50% + 재지시/디버깅 15% + 최종 확인 20% | CRUD, 보일러플레이트, 설정, 마이그레이션, DTO |
| **중가속** (비즈니스 로직) | **0.6~0.7x** | 지시/설계 20% + AI 생성 대기 5% + 리뷰/이해 35% + 재지시/수정 25% + 최종 확인 15% | 서비스 로직, 유효성 검증, 도메인 규칙, API 연동 |
| **저가속** (복잡/창의적) | **0.8~0.9x** | 사람 설계 35% + AI 보조 10% + 리뷰 20% + 디버깅/수정 25% + 검증 10% | 아키텍처 결정, 복잡한 디버깅, 성능 최적화, 동시성 |

### 단계별 시간 산정

- **코드 구현 (지시+생성+리뷰)**: 전통적 수동 코딩 시간 × 작업 유형 승수. 프롬프트 작성·AI 출력 리뷰·반복 수정·재지시/디버깅·전체 코드 이해 포함.
- **자체 QA (AI 테스트 생성 + 사람 검증)**: 전통적 자체 QA × **0.5~0.6x** (사람이 시나리오 적절성·커버리지 검증).
- **코드 리뷰 대기 + 피드백 반영**: 대기 **0.5~1영업일**(변동 없음). 1차 반영 전통 시간 × **0.4x**, 추가 라운드 1차의 **0.5x**(재요청 확률 ~30%). 기대값 = 1차 + (0.3 × 추가 대기 0.5일 + 추가 반영). 대기 중 다음 PR 병렬 진행.
- **QA**: QA 팀 검증(해당 시 **0.5~1영업일**, 변동 없음). 대기 중 다음 PR 병렬 진행.

### 프론트엔드: 두 가지 산정 (CRITICAL)

| 모드 | 구현 승수 | 자체 QA 승수 | 설명 |
|------|-----------|-------------|------|
| **꼼꼼 리뷰** | 위 표와 동일 | 위 표와 동일 | 코드 전체를 완벽히 이해 (백엔드 동일 수준) |
| **빠른 리뷰** | 위 표의 **0.7x** | 위 표의 **0.7x** | 동작 확인 위주 |

예: 중가속 FE 전통 8h → 꼼꼼 8h×0.65=5.2h / 빠른 8h×0.65×0.7=3.6h. 일정표에 `(꼼꼼/빠른)` 병기.

### 산정 근거 및 한계 (출처)

- METR RCT (2025, 가장 엄밀): 숙련 개발자 AI 사용 시 **19% 느려짐** → 후속(2026) **18% 빨라짐**.
- 업계 자기보고 평균: 코딩 활동 **33~36% 시간 단축** (대기업 보고, 자기 평가 포함).
- 작업 유형별 자기보고: 고반복 **50~80% 단축**, 비즈니스 로직 20~40%.
- AI QA: 분석 6~10x 빨라짐 (OpenObserve), 테스트 시간 50% 단축 (ContextQA).
- **주의**: 자기보고와 실제 측정 사이 큰 괴리(METR). 벤더 보고는 최적 조건 기준. **이 승수는 초기값**이며 경험이 쌓이면 프로젝트별로 보정.

## 3. 파이프라인 병렬화

```
시간 →
PR-1: [구현+자체QA] → [리뷰 대기] → [피드백 반영] → [QA 대기] → 완료
PR-2:                  [구현+자체QA] → [리뷰 대기] → [피드백 반영] → ...
                       ↑ PR-1 리뷰 대기 중 PR-2 착수
```

1. PR-N을 리뷰에 제출하면 즉시 PR-N+1 구현 착수(의존성 없는 경우).
2. 의존하는 경우: 선행 PR이 리뷰 제출된 후 착수 가능(머지 대기 불필요, 인터페이스 확정).
3. 리뷰 피드백 도착 시: 현재 작업 중단점까지 마무리 → 반영 → 복귀.
4. 컨텍스트 스위칭 비용: PR당 **30분** 추가.

캘린더 매핑: 시작일부터 영업일 가용 시간 적용, 공휴일/휴가 건너뜀, 리뷰/QA 대기는 영업일 기준(대기 시간은 다른 PR로 채움, 마지막 PR은 대기가 그대로 반영).
