# Claude Code 개인용 계정 자동 전환

기본 Claude Code 프로필의 여러 세션을 유지하면서 계정 인증을 함께 교체한다.
우선 계정의 사용률이 90% 이상이면 대체 계정으로 옮기고, 우선 계정의 한도가
초기화되어 다시 쓸 수 있으면 돌아온다. 계정별 이메일은 공개 코드에 넣지 않고
`private/claude/account-switcher/config.json`에 저장한다.

Python 3.10 이상, macOS 기본 Security/CoreFoundation 프레임워크와
`/usr/bin/security`를 사용한다. 추가 패키지나 외부 계정 전환기는 설치하지 않는다. 2026-11-13에 Claude Code 2.1.323의 기본
`~/.claude` 프로필에서 실제 계정 전환과 공식 CLI의 로그인 읽기를 확인했다.

버전 숫자 일치 대신 설치된 실행 파일의 인증 구조·잠금 경로와 공식 CLI의
`auth status --json` 결과를 검사한다. 패치 버전이 바뀌어도 이 조건을 만족하면
계속 동작한다. 실제 저장 구조나 로그인 방식이 달라지면 인증을 덮어쓰지 않는다.
`config.json`의 `supported_version`은 확인 당시의 참고 버전이다.

## 최초 설정

```sh
tool="$HOME/git/mac-setup/claude/account-switcher/switcher.py"
python3 "$tool" init --primary personal@example.com --fallback work@example.com --threshold 90
```

이 컴퓨터의 계정 우선순위 설정은 이미 초기화했다. `init`은 기존 설정을 덮어쓰지
않는다. 다음 설정부터 진행한다.

1. 현재 계정의 Keychain 접근을 최초 한 번 허용한다. 아래 명령만 macOS 확인창을
   띄울 수 있다. 사용자가 직접 실행하고, 계속 사용할 Python 실행 파일인지 확인한
   뒤 접근을 허용한다. 지속적인 실행에는 일회 허용 대신 지속적인 접근 승인이 필요하다.

   ```sh
   python3 "$tool" authorize
   ```

   현재 계정이 설정된 두 계정 중 하나인지 서버에서 확인하고 Keychain에 등록한다.
   토큰은 화면, 로그, 프로세스 인자, 평문 파일로 내보내지 않는다.

2. 다른 계정을 최초 한 번 로그인한다. 현재 회사 계정이라면 다음 명령을 실행한다.

   ```sh
   python3 "$tool" enroll primary
   ```

   공식 `claude auth login --email ...`을 실행하므로 브라우저 로그인이 필요하다.
   나가는 계정은 먼저 저장하며 `/logout`은 실행하지 않는다. 로그인 페이지에서
   이메일을 확인한다. 실제 계정이 기대한 이메일과 다르면 등록을 거부한다.
   이미 원하는 계정으로 로그인해 두었다면 `capture primary` 또는 `capture fallback`을 쓴다.
   브라우저가 기존 회사 계정을 자동 선택하면 CLI에 출력된 로그인 링크를 개인
   프로필이나 시크릿 창에서 열어 로그인한다. 인증 코드가 표시되면 해당 CLI
   프롬프트에 직접 입력한다. 다른 이메일로 인증하면 등록을 거부한다.
   공식 로그인이 Keychain 항목을 새로 만들면 `authorize` 승인이 다시 필요할 수 있다.

3. 화면 조작 없는 읽기와 사용량 조회를 확인한다.

   ```sh
   python3 "$tool" doctor
   python3 "$tool" once
   ```

   `doctor`는 두 계정의 등록, 현재 계정, 버전과 팝업 없는 Keychain 읽기를 확인한다.
   `once`는 계정 교체와 토큰 갱신을 하지 않는다. 현재 인증이 만료된 계정은
   조회 불가로 표시될 수 있다. `authorize` 후에도 권한이 거부되면 자동 실행을
   활성화하지 말고 Python 실행 파일에 대한 Keychain 승인을 확인한다.

4. 두 계정 조회가 정상이라면 백그라운드 서비스를 설치한다.

   ```sh
   python3 "$tool" service-install
   ```

   macOS launchd에서 실행되어 터미널을 닫아도 계속 동작한다. 시작 전 두 계정의
   등록과 메타데이터 조회를 검사한다. 기존 Claude 세션은 종료하지 않는다.
   이 단계부터 실제 계정 인증을 교체한다.

5. 실행 중인 세션도 교체 뒤 새 계정으로 옮기려면 `~/.claude/settings.json`의
   `hooks`에 `Stop`과 `StopFailure` 항목을 같은 내용으로 추가한다(동작은 「운용」 절).

   ```json
   "Stop": [{"hooks": [{"type": "command", "timeout": 10,
     "command": "python3 $HOME/git/mac-setup/claude/account-switcher/refresh_hook.py"}]}]
   ```

   훅은 Keychain을 읽지 않는다. 자기 대화 기록 끝에서 한도 오류만 확인하고, 교체 기록이
   없으면 세션 등록 파일과 프로세스 목록은 읽지 않고 끝난다.

## 규칙

| 조건 | 동작 |
|---|---|
| 우선 계정이 모든 확인된 한도에서 90% 미만 | 우선 계정 사용 |
| 우선 계정이 90% 이상, 대체 계정은 여유 있음 | 대체 계정으로 전환 |
| 우선 계정 초기화 시각 도달 | 사용량 재조회 후 복귀 판단 |
| 주간 또는 모델별 사용률이 90% 이상 | 우선 계정 복귀 보류 |
| 사용량 조회 실패 또는 데이터 누락 | 해당 계정으로 전환하지 않음 |
| 두 계정 모두 90% 이상 | 추가 전환을 멈추고 초기화 재확인 |

서버가 알려준 초기화 시각을 파일에 저장한다. 시각이 지났다는 이유만으로 사용량을
0%로 바꾸지 않는다. 최신 사용량이 실제로 확인되어야 복귀한다. 보고된 모델별
주간 한도도 보수적으로 모두 검사하므로, 사용하지 않는 모델의 한도가 복귀를
막을 수 있다. 누락된 사용률은 0%로 보지 않는다.

조회 간격은 지금 쓰는 계정의 가장 높은 한도 사용률이 기준(90%)에서 얼마나 떨어져
있는지로 정한다: 30%p 이상이면 9분, 15%p 이상이면 5분, 5%p 이상이면 2분, 그보다
가까우면 `poll_seconds`(60초). 사용률 API는 조회의 절반가량에 HTTP 429로 답했기
때문이다(2026-11-13). 가장 긴 간격은 할일 대시보드가 이 기록을 믿는 10분보다 짧게
둔다. 조회가 실패하면 마지막 사용률로 간격을 정한다. 초기화가 더 빠르면 그 직후
재조회하고, 서버가 조회 제한을 응답하면 해당 대기 시간을 지킨다. 같은 주기의 검증된 대상 사용률을
재사용하므로 전환 직전 같은 사용률 API를 중복 호출하지 않는다. 절전이나 재시작 후에도 저장한
초기화 시각을 사용한다. macOS 인증 캐시를 고려해 교체 뒤 45초 동안 재교체와
나간 계정의 토큰 갱신을 보류한다. 두 계정의 5시간·주간 한도 모두 같은 90%
기준을 적용한다. 90%는 엄격한 사용 상한이 아니며, 여러 세션의 요청과 캐시
반영 지연 때문에 실제 한도 오류가 먼저 발생할 수 있다.

## 인증과 복구

- 일반 실행에서는 macOS 확인창을 금지한다. `authorize`만 명시적으로 허용한다.
- 기본 계정의 OAuth와 계정 메타데이터만 교체한다. 대화 파일과 프로젝트,
  기존 설정, MCP 로그인은 교체하지 않는다.
- 기본 Claude 항목(`Claude Code-credentials`)은 `/usr/bin/security`로만 읽고 쓴다.
  쓰기는 Claude Code 2.1.323과 같은 명령 `add-generic-password -U -a … -s
  "Claude Code-credentials" -X <hex>`이다. 명령이 4032자 이하면 `security -i`
  표준 입력으로, 넘으면 Claude Code처럼 인자로 넘긴다. MCP 연동 인증이 든 로그인은
  약 12KB라 인자로 넘어가며, `security`가 끝날 때까지 프로세스 목록에 보인다
  (Claude Code 자신의 갱신과 같은 노출). 평문 파일에는 저장하지 않는다.
- 다른 실행 파일로 쓰면 그 항목의 파티션 목록이 그 실행 파일 것으로 바뀐다.
  Claude Code는 `security`(`apple-tool:`)로 읽으므로 모든 세션이 읽을 때마다
  승인창을 띄운다. 2026-11-13 11:23 `/usr/bin/ruby`로 쓴 뒤 목록에 `apple:`만
  남아 승인창이 쏟아졌다(securityd 로그 「ACL partition mismatch: client apple-tool:」).
- 로그인 항목 읽기·쓰기나 호환성 검사가 실패하면 `halt`를 남기고, 그 뒤로는
  로그인 항목을 읽지 않는다(측정은 승인창 없는 읽기로 계속한다). `security
  find-generic-password`가 승인창 없이 되는지 확인한 뒤 `resume`으로 푼다.
- 전환 중 검증에 실패하면 암호화된 복구 기록을 남기고 다음 주기에 일관성을
  복원한다. 임시 Keychain 항목을 만드는 테스트는 주기 실행에서 수행하지 않는다.
- 교체 직전 Claude가 갱신한 최신 인증을 다시 보관한다. 쉬고 있는 계정의
  access token은 필요할 때 갱신하고, 갱신된 refresh token을 먼저 Keychain에 보존한다.
- 토큰 소유 이메일·계정 UUID·조직을 서버에서 확인한다. 같은 토큰의 동일 신원은
  메모리에 재사용하며 토큰이나 계정 메타데이터가 바뀌면 다시 확인한다.
- Claude의 `.oauth_refresh.lock`, 기존 프로필 `.lock`, 전역 설정 `.lock` 순서로
  잠금을 잡는다. 다른 프로세스의 잠금은 오래됐어도 빼앗지 않는다.
- 교체 전 Keychain에 복구 기록을 남긴다. 설정 저장 실패 시 원래 인증으로
  복원하고, 프로세스 종료로 중간에 끊겼으면 다음 적용 실행에서 일관성을 복원한다.
  중간에 새 로그인이 생겨 어느 계정인지 확정할 수 없으면 덮어쓰지 않고 멈춘다.
- Anthropic 고정 HTTPS 주소의 인증·프로필·사용량만 호출한다. 프록시 환경변수와
  리다이렉트를 따르지 않으며 모델 추론 요청은 보내지 않는다.

등록된 인증은 Keychain 서비스 `local.mac-setup.claude-account-switcher`에 저장한다.
공개 코드에는 인증을 저장하지 않는다. `private/claude/account-switcher/`에는 이메일,
사용량, 초기화 시각, 오류 종류만 저장하며 디렉터리는 `0700`, 파일은 `0600`이다.

## 운용

```sh
python3 "$tool" status             # 저장된 상태만 확인
python3 "$tool" measure-status     # 주기별 토큰·한도 사용률 측정 결과
python3 "$tool" once               # 인증을 바꾸지 않는 사전 확인
python3 "$tool" once --apply       # 한 번 실제 판단·교체
python3 "$tool" run --apply        # 현재 터미널에서 계속 실행
python3 "$tool" resume             # 키체인 오류로 멈춘 halt 해제
python3 "$tool" service-uninstall  # 백그라운드 서비스 중지·제거
```

동일 상태 디렉터리에서는 하나의 데몬만 실행한다. 교체 뒤 새로 연 세션은 바로 새
계정을 쓴다. 이미 실행 중인 세션은 Claude Code 2.1.323이 들고 있는 토큰을 계속 쓰다가
그 토큰이 만료되거나, 401이 나거나, 사용 한도 오류가 난 다음 요청에서야 저장된 로그인을
다시 읽는다(2026-11-13 15:21 교체 뒤 실행 중 세션은 15:28에도 옛 계정 캐시를 읽었다).

그래서 서비스는 교체 시각만 상태 디렉터리의 `session_refresh`에 기록하고, 각 세션의
`Stop`·`StopFailure` 훅(`refresh_hook.py`, 설정은 최초 설정 5단계)이 턴이 끝날 때 세션을
다시 띄운다. cmux는 cmux 안에서 시작한 프로세스만 탭을 조작하게 하므로(설정
`automation.socketControlMode` 기본값 `cmuxOnly`) launchd 서비스는 세션 탭에 입력하지
못한다(2026-11-13 확인). 훅은 세션이 한도 오류로 멈췄거나, 교체가 8시간 안이고 세션이
그보다 먼저 시작했을 때만 분리한 도우미를 띄우고 바로 끝난다. 도우미는 세션보다 늦은
교체를 기다린 뒤 아래 조건을 기다렸다가 자기 탭에 내장 `/restart`를 넣는다(`refresh.py`).
`/restart`는 같은 pid에서 다시 실행되고 같은 세션 ID로 대화를 이어 간다(2026-11-13 시험
세션에서 확인, 등록 파일 `startedAt`만 바뀐다).
- 대상: cmux 탭에서 돌고 마지막 교체 전에 시작한 세션. 교체보다 한도 오류가 먼저 온
  세션은 전환기가 다음 조회(최대 9분 간격)에서 교체할 때까지 3초마다 최대 15분 기다린다
  (2026-11-16 11:27에 한도, 11:32에 교체였던 세션이 재시작 없이 멈춰 있었다).
- 조건: 상태가 `idle`이거나 마지막 응답이 사용 한도 오류, 입력창(`❯`)이 비어 있음,
  자식 셸(백그라운드 Bash·Monitor)이 없음, 서브에이전트 기록이 2분 안에 바뀌지 않음.
  도우미는 3초마다 최대 10분 기다린다. 한도 오류 뒤에 쌓인 백그라운드 작업 알림
  (`<task-notification>`)은 사용자 입력으로 보지 않는다(2026-11-16 11:08 한도에 멈춘
  세션에 알림이 이어 들어와 재시작 뒤 「이어서 해줘」가 빠졌다).
- 한도 선택창: 「What do you want to do?」 창이 입력창을 가리면 Esc로 닫고(「Stop and
  wait for limit to reset」과 같다) 다음 확인에서 입력창을 본다(2026-11-16 11:35 아직
  한도인 세션을 다시 띄우자 이 창이 떠 `restart_unconfirmed`로 끝났다).
- 이어서: 한도 오류로 멈췄던 세션은 다시 뜬 뒤 「이어서 해줘」를 넣는다
- 그대로 두는 세션: 10분 안에 조건이 안 맞은 세션은 다음 턴이 끝날 때 다시 본다.
  cmux 밖 세션과 8시간 안에 턴이 끝나지 않은 세션은 토큰 만료 때 넘어온다. 한도에
  멈췄는데 15분 안에 교체가 없으면(두 계정 모두 한도 등) 아무것도 넣지 않는다.
- 결과: 상태 디렉터리의 `session-restarts.log`에 세션 ID 앞 8자리와 `restarted`·
  `restarted_and_continued`·`no_switch`·`not_ready`·`restart_unconfirmed` 중 하나를 남긴다.
- 상태줄의 「← N agents」는 새 세션에도 뜨는 안내라 판정에 쓰지 않는다. Claude Code가
  띄우는 `caffeinate -i -t 300`도 작업이 끝난 뒤 최대 5분 남으므로 쓰지 않는다.

각 대화 맥락은 그대로 남는다. 별도 `CLAUDE_CONFIG_DIR`,
환경변수 토큰, API 키, 외부 모델 제공자 설정이 있는 실행은 지원하지 않는다.
두 계정 모두 막히면 전환기만 기다리며, 실행 중인 Claude의 요청을 강제로 중단하거나
이미 실패한 요청을 자동으로 재시도하지 않는다. 기본 서비스 로그는 상태 디렉터리에
저장한다. 서비스 제거는 현재 Claude 계정이나 저장된 인증을 삭제하지 않는다.

## 주기별 토큰·한도 사용률 측정

2026-11-13부터 기존 백그라운드 서비스가 조회 주기마다 두 계정의 한도 사용률과
로컬 대화 기록에서 새로 관측된 토큰 카운터 증가량을 함께 저장한다. 추가 모델
요청은 보내지 않는다. 정상 전환기 조회 결과를 재사용하고, 버전·인증 검사로
계정 교체가 중단된 경우에는 별도로 사용률만 조회한다. 서버의 조회 제한과
`Retry-After`를 지킨다. 관측 간격은 조회 간격(1~9분)을 따른다.

```sh
python3 "$tool" measure-status
```

`private/claude/account-switcher/measurements/YYYY-MM-DD.jsonl`에 일자별로
기록하고 30일을 보관한다. 일자 기준은 UTC다. 최신 관측은 같은 상태 디렉터리의
`measurement_latest.json`, 조회 실패는 `measurement_error.json`에 저장한다.
대화 내용·도구 결과·토큰 문자열·요청 식별자는 기록하지 않는다. 기록 파일은
`0600`, 디렉터리는 `0700`이다.

로컬 Claude Code 대화 기록의 `message.usage`를 입력·캐시 생성·캐시 읽기·출력으로
나눠 집계한다. `message.id`별 카운터 최댓값의 증가분만 더해 스트리밍 콘텐츠
블록과 복제된 세션을 중복 계산하지 않는다. 시작 직후의 기록은 기준점으로만
사용하고, 이후 구간부터 증가량을 센다. 요청 식별자는 메모리에만 보관한다.

사용률 차이는 같은 계정·같은 한도·같은 초기화 구간에서만 계산한다. 초기화,
감소한 카운터, 오래된 조회값, 계정 교체, 긴 관측 공백은 사용률 차이나 토큰의
계정 추정에서 제외한다. 요약의 최대치는 관측 간격 45~90초에서의 증가폭이며
정확한 연속 60초 최대치가 아니다. 100%에 닿은 관측은 포화 상태로 표시한다.
로컬 토큰과 서버 차감에는 스트리밍·집계 반영 지연이 있고, 다른 기기와 Claude
웹 사용량은 로컬 토큰에 없으므로 둘의 대응은 추정치다. 0%포인트 변화도 실제
토큰 소모가 없었다는 의미가 아니다.

측정용 Keychain 읽기는 `kSecUseAuthenticationUIFail`로 암호창을 금지한다.
현재 항목을 읽지 못하면 암호화된 기존 계정 보관본을 사용한다. 활성 계정의
보관된 토큰이 만료되면 해당 계정은 조회 불가로 표시하며, 활성 계정의 오래된
refresh token으로 갱신하지 않는다. 비활성 계정의 만료 토큰만 갱신해 보관한다.
측정은 Claude Code의 현재 인증 항목과 계정 메타데이터를 쓰지 않는다.

2026-11-13에 패치 버전 고정 검사로 중지되던 문제와 Keychain 읽기·쓰기
호환성을 수정하고 실제 자동 전환을 복구했다. 측정 결과로 90% 기준을 자동
변경하지 않는다. 암호창을 띄운 과거 임시 항목 테스트는 자동으로 실행하지 않는다.

## 2주 관측 예약

2026-11-13에 사용자가 요청한 전환 기준은 90%다. 다음 명령으로 현재 설정과
측정 계획을 조회한다.

```sh
python3 "$tool" status
python3 "$tool" monitor-status
```

`monitor-start --days 14`는 시작 시각부터 14일간 관측을 예약한다. 이미 진행 중인
계획이 있으면 같은 계획을 반환하며 종료 시각을 연장하지 않는다. 시작할 때와
이후 매 24시간마다 로컬 보고서를 만들고, 종료 시각에는 전체 기간의 최종
보고서를 만든다. 컴퓨터가 꺼져 있거나 잠자기 중이면 다음 서비스 실행 시
검토한다. 메타데이터 조회 제한 때문에 실제 조회 간격이 길어진 경우도 보고한다.

보고서는 `private/claude/account-switcher/monitoring/<시작시각>/`에 저장한다.
`latest.md`는 최신 누적 요약, 날짜별 Markdown·JSON은 각 검토 시점의 보고서,
`final.md`·`final.json`은 최종 보고서다. 보고서 경로는 `monitor-status`의
`last_report`에도 나온다. 관측이 끝나면 측정용 추가 조회와 원시 스냅샷 수집은
멈추고 보고서는 보존한다. 계정 전환 서비스의 기존 동작은 별도로 유지한다.

개인 계정의 5시간 한도에서 실제 Opus 5.5 사용 구간이 있는지 확인하고, 한도별
45~90초 사용률 증가폭, 남겨 둔 여유와의 비교, 조회 실패·누락·긴 공백을 정리한다.
다른 모델만 사용했거나 개인 계정 사용이 없으면 근거 부족으로 표시한다.
관측값으로 향후 안전을 보장하거나 전환 기준을 자동 변경하지 않는다.
이 검토는 새 모델 요청·화면 조작·외부 메시지 전송 없이 기존 서비스에서 실행한다.
