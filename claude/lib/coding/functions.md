For Python code, also Read `~/.claude/lib/coding/functions-python.md`; for frontend code, `~/.claude/lib/coding/functions-frontend.md`.

- Function unit: make a function the unit a caller uses; extract part of a function only when another caller needs that part or the extraction narrows the scope of the variables it touches, and keep the other steps in place.
- Local variables: inline a value used once while its line stays within the repository formatter's line length (110 characters where none is set); past that, give it a named variable.
- Branches: when an if/else chain that switches on a kind repeats in several places, replace it with polymorphism (a class or handler per kind), or with one function holding the switch when that removes the repetition with fewer syntax elements; keep all kind-specific behaviour on that one hierarchy instead of a second hierarchy that mirrors it. Use a module-constant table and a loop for same-shape repetition and `~/.claude/lib/coding/domain.md` State for state transitions; if dispatch is exhaustive over an enum, test that every member has an entry.
- Flag arguments: when callers pass a fixed value to pick which branch runs (`close(loan, lost=True)`), split the function per branch with Remove Flag Argument (`report_lost(loan)`, `return_book(loan)`), sharing common steps through an extracted function; keep the parameter when its value comes from data (a request field, a stored column); merge near-duplicate functions with Parameterize Function only when they differ in a value the body computes with (`extend_one_week` and `extend_two_weeks` → `extend(loan, days)`).
- One reason to change: an extracted function does only what its name promises; put guards in the caller, whose loop skips or returns early.
- Query or command: a function either returns a value without side effects or mutates and returns nothing; split one that does both. An entity method such as `entity.change()` may mutate in memory and return the result, and a repository `create`/`save` may return the id or entity it produces; for a command use case's return value, Read `~/.claude/lib/coding/architecture.md` and follow its Command or query use case item.
- Same call N times → table + loop: turn 4+ explicit calls of one function with different arguments into a module-constant list of argument combinations iterated in a loop.
- One conditional expression per expression: keep at most one conditional expression (`a if c else b`, `c ? a : b`) in an expression, and write an if statement when the choice needs another condition.
- Defaults only where a caller omits the value: remove a parameter default once every call site passes the value explicitly.
- Collection parameters are non-nullable: pass an empty collection for "no filter"; scalars may be null.
- Parameter object: when two or more values go together into two or more functions and together name one thing (`start_date` and `end_date` as a period), replace them with one value object by Introduce Parameter Object, and move the rules on those values into it (start before end).
- Explicit fields after a spread: when an explicit value must win over a same-named key in the spread, put it after the spread.
- Immutable copy: a function that would mutate an input map or list returns a modified copy as a new object.
