- 404 vs 200 + null: `GET /resources/{id}` for a missing resource returns 404 (`NotFound`); a condition-based single lookup ("the in-progress amendment") with no match returns 200 with a null field.
- Partial update: the request names the fields to change, by `update_mask` in proto and by the keys present in a JSON body. Set each named field to the sent value, clear it when that value is null (JSON) or empty (proto), and leave every other field as it is; a clear on a field that cannot be empty fails with 400 (`INVALID_ARGUMENT`).
- OpenAPI spec with every endpoint change: when a similar endpoint is documented, update the OpenAPI yaml in the same change; put the endpoint in the directory and file pattern of its sibling specs and register it the way they are registered (a `$ref` under the root spec's `paths:`); file = top-level `post:`/`get:` + summary/tags/operationId/requestBody·parameters/responses 200/202/400/401/403/500.
- Request DTO defaults: declare a form field required in the request DTO and leave its initial value to the UI; keep a default only when omitting the field is a meaningful business state (an empty targeting map `{}` meaning no targeting, with its reason in a comment); remove a default that validation rejects anyway (`budget=0`) or that the UI also defines.
- Idempotent triggers: an endpoint that moves money or sends messages takes an idempotency key, or returns the job already running for the same scope, date and action, so a repeated call starts nothing new.
- Unknown is null: a count or total the source has not set yet is null in the response, never 0.
- No empty set means all: a request that acts on a set of records never treats an empty or omitted set as all of them; send an explicit flag for the whole scope, and have the client repository reject an empty set before sending.
