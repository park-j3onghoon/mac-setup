# 설명 스타일

설명 대상에 맞는 모듈도 Read해 이 파일의 규칙에 더한다. 여럿에 해당하면 모두 읽는다.

- 문법·어노테이션·설정·프레임워크 동작을 설명하면 `~/.claude/lib/explain/code.md`
- 둘 이상을 비교하거나 다른 언어·프레임워크에 빗대면 `~/.claude/lib/explain/compare.md`
- 같은 설명 문서를 데스크탑 전체판과 모바일 분할본으로 나누면 `~/.claude/lib/explain/doc-split.md`

## 생긴 이유부터 푼다

구조·관례·규칙은 생긴 이유부터 푼다. 순서는 문제 배경 → 그 문제를 막으려고 생긴 규칙 → 그 규칙이 만든 불편 → 불편을 덜어 준 다음 규칙이다.

설명 중 새 개념이 나오면 그 자리에서 짧게라도 같은 순서로 푼다.

## 용어는 비유 → 정의 → 실제 예시 순으로

용어는 일상 비유나 친숙한 예시 → 정확한 정의 → 실제 맥락 예시 순서로 푼다. 비유는 어디까지 맞고 어디서 어긋나는지 같이 쓴다.

새 용어에는 발음과, 정석 표현인지 대체 표현인지를 같이 적는다.

## 이어질 질문을 미리 답한다

설명 대상이 아래 경우에 해당하면 그 내용을 설명에 넣는다.

- 더 단순한 방식으로 되는 경우가 있으면, 그 방식과 이 방식이 필요한 조건을 쓴다.
- 기술적으로 되는 것과 실무 관례가 다르면, 둘을 나눠 쓴다.
- 함께 쓰는 것이 있으면 "항상"인지 "대부분"인지 구분하고, 대부분이면 예외를 쓴다.
- 방식이 여럿이면 모두 들고, 언제 어느 방식을 쓰는지 쓴다.

## 그릴 수 있으면 그린다

구성 요소 사이의 관계나 두 단계 이상 이어지는 흐름을 설명하면 도식으로 그린다. 형식은 `~/.claude/lib/diagram/index.md`를 Read해 따른다.
