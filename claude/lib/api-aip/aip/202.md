- `google.api.field_info`(`google.api.FieldInfo` 타입)는 이 AIP나 `FieldInfo` 정보를 쓰는 다른 AIP가 명시한 경우에만 단다; 그런 경우에도 이 AIP의 지침이 적용된다.
- 원시 타입 필드의 구체 형식은 `FieldInfo.Format` enum 값을 `(google.api.field_info).format` 확장 필드에 넣어 밝힌다.
- `UUID4`: RFC 4122의 UUID 버전 4 값; 반드시 `string` 필드에만 쓴다; 서비스가 전부 소문자로 정규화해도 된다(`F47AC10B-58CC-0372-8567-0E02B2C3D479` → `f47ac10b-58cc-0372-8567-0e02b2c3d479`); 그래서 같음 비교는 반드시 단순 문자열 비교로 하지 않고 반드시 RFC 4122 준수 구현으로 한다.
- `IPV4`: RFC 791의 IPv4 주소; 반드시 `string` 필드에만 쓴다; 서비스가 옥텟마다 앞 0을 떼어 줄여도 된다(`001.022.233.040` → `1.22.233.40`); 같음 비교는 반드시 단순 문자열 비교로 하지 않고 반드시 RFC 791 준수 구현으로 한다.
- `IPV6`: RFC 4291의 IPv6 주소; 반드시 `string` 필드에만 쓴다; 서비스가 RFC 5952대로 소문자·0 압축으로 정규화해도 된다(`2001:0DB8:0::0` → `2001:db8::`); 같음 비교는 반드시 단순 문자열 비교로 하지 않고 반드시 RFC 4291 준수 구현으로 한다.
- `IPV4_OR_IPV6`: IPv4나 IPv6 어느 쪽이든 될 수 있는 필드이고, 각 규칙은 위 `IPV4`·`IPV6`과 같다.
- 형식이 없던 기존 필드에 형식을 더하는 것은 하위 호환이 아니다(그 필드가 늘 그 형식을 따랐으면 예외); 기존 형식을 다른 형식으로 바꾸는 것은 어떤 경우든 하위 호환이 아니다.
- 새 `FieldInfo.Format` 값은 반드시 IETF가 승인한 RFC나 Google이 승인한 AIP가 규정하는 형식이어야 한다.
