```proto
message Book {
  option (google.api.resource) = {type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}" style: DECLARATIVE_FRIENDLY};
  // name 등 필드
}
```
- declarative-friendly 리소스는 생명주기 관리에 반드시 강한 일관성(strongly-consistent)을 지닌 표준 메서드만 쓰고, 다른 declarative-friendly 규칙(마지막 줄)도 반드시 따른다; `google.api.resource`에 `style: DECLARATIVE_FRIENDLY`를 달아 이 스타일을 따른다고 밝힌다(권장).
- 업데이트가 반영되기까지 몇 초 넘게 걸리는 리소스는 변경이 진행 중임을 알리는 `bool reconciling` 필드를 둔다(권장); 이 필드는 반드시 `OUTPUT_ONLY`.
- 리소스의 현재 상태가 사용자가 의도한 상태와 다르고 시스템이 둘을 맞추는 중이면 반드시 `reconciling`을 `true`로 둔다; 조정에 들어간 원인이 사용자 동작이든 시스템 동작이든 같다.
- `GET` 요청엔 반드시 의도한 상태가 아니라 리소스의 현재 상태를 돌려준다.
- 다른 AIP가 declarative-friendly 리소스에 더하는 규칙: 커스텀 메서드를 쓰지 않는다(권장, `~/.claude/lib/api-aip/aip/136.md`); repeated 필드 변경은 반드시 표준 `Update`로 하고 `Add`·`Remove` 메서드를 반드시 두지 않는다; 표준 필드를 반드시 둔다(`~/.claude/lib/api-aip/aip/148.md`); `etag` 필드를 반드시 둔다(`~/.claude/lib/api-aip/aip/154.md`); 실행 없이 검증만 하는 변경 검증을 제공한다(권장, 변경 검증 지침 쪽은 리소스를 바꾸는 메서드에 `bool validate_only`를 반드시 두라고 한다); soft delete는 구현하지 않는다(권장), 단 지운 리소스의 ID를 다시 쓸 수 없으면 soft delete와 undelete RPC를 반드시 구현한다(`~/.claude/lib/api-aip/aip/164.md`).
