- 필드 이름은 반드시 `lower_snake_case`; 단어는 숫자로 시작하지 않고 앞·뒤·연속 밑줄이 없다(반드시); repeated 필드는 반드시 올바른 복수형(`books`), 단수 필드는 단수형(권장). JSON 쪽 이름은 자동 변환된다.
- 올바른 미국 영어(권장); 같은 개념엔 API 사이에도 같은 이름(권장); 불필요한 단어를 빼되 모호하거나 지나치게 일반적인 이름은 피한다(권장).
- 잘 알려진 약어는 약어로 쓴다(권장): `config`, `id`, `info`, `spec`, `stats`; 단위도 약어 접미사(권장): `distance_km`, `width_px`.
- 형용사는 명사 앞(권장): `collected_items`(`items_collected` 아님). 의도·동작을 담은 동사형 이름은 반드시 금지(`collect_items` 아님).
- 전치사(`with`, `for`, `at`, `by`)를 넣지 않는다(권장): `error_reason`(`reason_for_error` 아님); 수량의 `per`는 예외.
- boolean은 `is` 접두어를 뺀다(권장): `disabled`(`is_disabled` 아님); 빼면 예약어가 되는 경우만 예외.
- 임의 URI는 `uri`, URL만 담는 필드는 `url`(권장).
- 언어 키워드와 겹칠 이름(`new`, `class`, `import` 등)은 피하고, 감싸는 메시지와 같은 이름의 필드는 두지 않는다(둘 다 권장).
- 바이너리는 `bytes`(권장); 저장 단계부터 base64 문자열이면 이중 인코딩을 피하려 `string`을 써도 된다.
- `name`(string): 모든 리소스에 반드시, 첫 필드(권장), IDENTIFIER(`~/.claude/lib/api-aip/aip/203.md`); `_name` 접미사는 다른 종류의 이름에 쓰지 않는다(권장).
- `parent`(string): 컬렉션의 부모 리소스 이름, 대부분의 List·Create 요청에 쓴다(권장).
- `display_name`(string): 반드시 사용자가 바꿀 수 있는 사람용 이름; declarative-friendly 리소스(`~/.claude/lib/api-aip/aip/128.md`)엔 둔다(권장); 고유성 요구 없이 63자 이하(권장). 회사명 같은 공식 명칭은 `title`(권장).
- 사람·동물 이름은 반드시 `given_name`·`family_name`, `first_name`·`last_name`은 반드시 쓰지 않는다.
- `create_time`(Timestamp, OUTPUT_ONLY): 반드시 생성 시각(시작이든 완료든 된다). `update_time`(Timestamp, OUTPUT_ONLY): 사용자가 바꾸면 반드시 갱신, 서비스 내부 변경이면 갱신해도 된다. 둘 다 declarative-friendly면 둔다(권장).
- `delete_time`(Timestamp, OUTPUT_ONLY): 반드시 soft delete 시각, soft delete가 아니면 반드시 비운다.
- `expire_time`(Timestamp): 리소스가 더는 유효하지 않은 시각(권장)이고, 만료를 나타내려면 반드시 `google.protobuf.Timestamp expire_time` 필드를 쓴다; 부정확해도 되지만 그 전에 만료하면 반드시 안 된다. `purge_time`: soft delete된 리소스가 영구 삭제될 시각(권장), 그 전에 purge하면 반드시 안 된다.
- `annotations`(`map<string, string>`): 클라이언트 도구용 소량 메타데이터로 둬도 된다; 반드시 Kubernetes annotation 제한을 따르고 키는 점(`.`) 네임스페이스를 요구한다(권장).
- IP 주소 필드는 반드시 `string`, 이름 `ip_address` 또는 `_ip_address` 접미사(`resolved_ip_address`), 형식 `IPV4`·`IPV6`·`IPV4_OR_IPV6`을 명시.
- `uid`(string, OUTPUT_ONLY): 시스템이 할당한 고유 ID, 반드시 UUID4이고 반드시 `UUID4` 형식 확장으로 명시; declarative-friendly면 둔다(권장).
- `google.api.field_info`(`google.api.FieldInfo` 타입)는 아래 형식 규칙이나 `FieldInfo`를 쓰는 다른 AIP(위 IP 주소·uid)가 명시한 경우에만 달고, 원시 타입 필드의 구체 형식을 `FieldInfo.Format` enum 값으로 `(google.api.field_info).format` 확장 필드에 넣어 밝힌다.
- `UUID4`(RFC 4122)·`IPV4`(RFC 791)·`IPV6`(RFC 4291)·`IPV4_OR_IPV6`(IPv4나 IPv6)은 반드시 `string` 필드에만 쓰고, 서비스가 정규화해도 된다(UUID4는 전부 소문자, IPV4는 옥텟마다 앞 0 제거, IPV6은 RFC 5952대로 소문자·0 압축); 같음 비교는 반드시 단순 문자열 비교 대신 그 RFC를 준수하는 구현으로 한다.
- 형식이 없던 기존 필드에 형식을 더하는 것은 깨는 변경이다(그 필드가 늘 그 형식을 따랐으면 예외); 기존 형식을 다른 형식으로 바꾸는 것은 어떤 경우든 깨는 변경이다.

```proto
message ExpiringResource {
  // google.api.resource 등 다른 annotation·필드
  oneof expiration {
    // UTC 만료 시각; 출력엔 늘 채우고, 생성 때 ttl을 줬으면 그 값으로 계산한다.
    google.protobuf.Timestamp expire_time = 2;
    // Input only. 이 리소스의 TTL.
    google.protobuf.Duration ttl = 3 [(google.api.field_behavior) = INPUT_ONLY];
  }
}
```
- 상대 만료 시간을 받으려면 반드시 `expiration`(또는 `{something}_expiration`)이라는 `oneof`를 정의하고 그 안에 `expire_time`과 별도의 `google.protobuf.Duration ttl`을 둔다; `ttl`은 반드시 `INPUT_ONLY`로 표시한다.
- 리소스를 조회할 땐 반드시 만료 시각을 `expire_time`에 담아 돌려주고 `ttl`은 비운다.
- TTL 고유의 의미에 기대는 API(TTL을 정수로 표현해야 하는 DNS 등)는 `int64 ttl` 필드를 써도 되고, 그 경우 `aip.dev/not-precedent` 주석을 단다(권장).
