```proto
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {

rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {post: "/v1/{project=projects/*}:translateText" body: "*"};

```
- 차례로 리소스 기반·컬렉션 기반·stateless 예시다. 이 AIP는 요청 필드를 정의하지 않는다; 리소스 기반 요청은 `~/.claude/lib/api-aip/aip/216.md`의 `PublishBookRequest`처럼 `string name = 1`(REQUIRED, `resource_reference`)을 둔다.
- 이름은 동사+명사(권장); 전치사(`For`, `With` 등)는 반드시 금지; 표준 동사(`Get`·`List`·`Create`·`Update`·`Delete`)는 쓰지 않는다(권장); `Async`는 반드시 금지, 즉시·장기 실행 구분이 필요하면 접미사 `LongRunning`을 써도 된다.
- HTTP: 데이터·상태 조회는 반드시 `GET`; 부작용이 있거나 리소스를 바꾸면 반드시 `POST`; 과금이 걸린 stateless 메서드는 반드시 `POST`; URL 길이 한도를 넘을 수 있는 조회는 `POST`여도 된다.
- URI는 반드시 `:` + 커스텀 동사이고 그 동사는 반드시 RPC 이름의 동사와 같으며, 여러 단어면 반드시 camelCase(`:translateText`). `body`는 `"*"`(권장, `GET`은 body 없음).
- 요청 `{RPC 이름}Request`, 응답 `{RPC 이름}Response`(둘 다 권장); 특정 리소스에 작용하면 리소스 자체를 돌려줘도 된다.
- 리소스 기반은 반드시 `name`이, 컬렉션 기반은 부모가 있으면 반드시 `parent`가 URI 경로의 유일한 변수; 컬렉션 키(`books`)는 반드시 리터럴.
- stateless는 범위 리소스 이름을 필드 이름으로(`project`), 동사·명사는 `:` 뒤에 둔다(둘 다 권장). declarative-friendly 리소스(`~/.claude/lib/api-aip/aip/128.md`)는 대체로 커스텀 메서드를 쓰지 않는다(권장).
