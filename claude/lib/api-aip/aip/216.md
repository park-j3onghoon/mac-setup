- 상태를 알리는 리소스는 enum을 쓰고 이름은 `State`(권장), 그 리소스에서만 쓰면 리소스 메시지 안에 중첩(권장): 같은 패키지의 최상위 enum끼리는 반드시 값 이름이 겹치지 않아야 한다. `Status`는 HTTP·gRPC 상태용이라 `State`를 쓴다.
- 이 enum을 담는 `state` 필드는 OUTPUT_ONLY로 동작·문서화하고(권장) Create·Update로 직접 설정하지 못하게 한다(권장; Update에서는 반드시 금지: `~/.claude/lib/api-aip/aip/134.md`).
- 0번은 `STATE_UNSPECIFIED = 0`(권장); 다른 값엔 enum 이름 접두어를 붙이지 않는다(권장). 고객에게 쓸모 있는 상태만 노출한다.
- 값 이름: 사용 가능하면 `ACTIVE`; 끝난 동작은 과거분사 `-ED`(`SUCCEEDED`, `FAILED`, `DELETED`, `SUSPENDED`), 진행 중 전환은 현재분사 `-ING`(`CREATING`, `DELETING`, `RUNNING`).
- 정지(resting) 상태는 사용자 조치가 없으면 유지된다: `ACCEPTED`, `ACTIVE`, `CANCELLED`, `DELETED`, `FAILED`, `SUCCEEDED`, `SUSPENDED`, `VERIFIED`.
- 활동(active) 상태는 보통 스스로 정지 상태 하나로 넘어간다: `CREATING`→`ACTIVE`, `DELETING`→`DELETED`, `PENDING`→`RUNNING`, `REPAIRING`→`ACTIVE`, `RUNNING`→`SUCCEEDED`, `SUSPENDING`→`SUSPENDED`.
- 상태 전환은 커스텀 메서드로: 동사+단수 리소스(`PublishBook`), 요청 `{메서드}Request`에 REQUIRED `name`, 응답은 리소스(LRO면 `Operation`)까지 권장; HTTP는 반드시 `POST`, URI는 반드시 `:{동사}`(`/v1/{name=publishers/*/books/*}:publish`), `body`는 반드시 `"*"`; 지금 상태에서 불가능한 전환이면 반드시 `FAILED_PRECONDITION`.
- 새 상태 추가는 깨는 변경이 아니다(해도 된다); 클라이언트가 새 값을 받을 수 있다고 문서화한다(권장). `ACTIVE`·`DELETED`처럼 둘뿐이면 enum 대신 `google.protobuf.Timestamp delete_time` 같은 필드를 고려한다.
