- 요청에 쓰이는 메시지·하위 메시지(리소스 포함)의 모든 필드에 반드시 `google.api.field_behavior`를 달고 `REQUIRED`·`OPTIONAL`·`OUTPUT_ONLY` 중 하나는 반드시 넣는다; `FIELD_BEHAVIOR_UNSPECIFIED`는 반드시 쓰지 않는다.
- 예외: 리소스의 `etag`(`~/.claude/lib/api-aip/aip/154.md`)엔 달지 않는다(권장); oneof 필드는 생략해도 되지만 동작을 주석으로 적는다(권장). AIP 예시에 annotation이 없는 `page_size`·`page_token`·`update_mask`도 필수가 아니므로 이 규칙을 따르면 `OPTIONAL`이다. 중첩 메시지 필드의 동작은 부모 필드와 독립이다(선택 부모 안의 필수 필드도 된다).
- `IDENTIFIER`: 반드시 리소스 `name`에만, 다른 필드(다른 리소스 참조 포함)엔 반드시 금지; create에선 입력을 받지 않고(OUTPUT_ONLY처럼) 변경 메서드에선 IMMUTABLE 입력으로 동작.
- `REQUIRED`: truthy 값(0·빈 값 아님, repeated·map은 1개 이상, 메시지는 truthy 필드 1개 이상)이 반드시 있어야 하고 없으면 오류(보통 `INVALID_ARGUMENT`); Update에선 필드 마스크에 없으면 생략해도 되고 있으면 반드시 값. 조건부 필수, 늘 응답에만 있는 필드, 사용자 입력이 없는 필드, false·0이 유효한 필드엔 반드시 쓰지 않는다.
- `OPTIONAL`: 필수가 아님; 요청·하위 메시지 필드에 쓰며 proto3 `optional` 라벨과 함께 써도 된다.
- `OUTPUT_ONLY`: 응답에만 나오는 리소스·하위 메시지 필드(응답 메시지 필드엔 불필요); 입력에 오면 서버는 반드시 값을 지우고 반드시 오류를 내지 않으며, 업데이트 마스크에 있어도 반드시 무시. 예: 타임스탬프, 서비스가 정하는 값.
- `INPUT_ONLY`: 요청에만 받고 응답엔 내지 않는다(권장); 드물게 쓴다(예: TTL, `~/.claude/lib/api-aip/aip/214.md`); 반드시 `REQUIRED`나 `OPTIONAL`과 같이 단다.
- `IMMUTABLE`: 생성 뒤 못 바꿈(예: 디스크 타입); Update에 같은 값이 오면 무시, 다른 값이면 `INVALID_ARGUMENT`(둘 다 권장); 조건부 불변엔 반드시 쓰지 않는다.
- `UNORDERED_LIST`: repeated 필드의 순서를 보장하지 않는다(정렬·무작위·호출마다 다른 순서 모두 된다).
- 호환: `OPTIONAL` 추가, `REQUIRED`→`OPTIONAL`, `IMMUTABLE`·`INPUT_ONLY` 제거, `name`에 `IDENTIFIER` 추가. 비호환: 기존·새 요청 필드에 `REQUIRED` 추가, 입력받던 필드를 `OUTPUT_ONLY`로, 출력하던 필드를 `INPUT_ONLY`로, `IMMUTABLE` 추가, `OUTPUT_ONLY`·`IDENTIFIER` 제거.
