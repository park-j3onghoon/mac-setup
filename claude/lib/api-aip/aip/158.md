```proto
message ListBooksRequest {
  string parent = 1 [(google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {child_type: "library.googleapis.com/Book"}];
  int32 page_size = 2;    // 예시 주석: 미지정이면 최대 50개, 최댓값 1000
  string page_token = 3;  // 이전 응답의 next_page_token
}
message ListBooksResponse {
  repeated Book books = 1;
  string next_page_token = 2;  // 다음 페이지가 없으면 빈 값
}
```
- 컬렉션을 돌려주는 RPC는 반드시 처음부터 페이지네이션을 넣는다: 기존 RPC에 나중에 넣으면 하위 호환이 깨진다.
- 요청엔 `int32 page_size`·`string page_token`(권장), 둘 다 반드시 필수가 아닌 필드로 둔다.
- `page_size`가 없거나 0이면 반드시 오류 없이 API가 정한 기본값; 최댓값보다 크면 최댓값으로 낮춘다(권장); 음수면 반드시 `INVALID_ARGUMENT`. 끝이 아니어도 요청보다 적게(0개 포함) 돌려줘도 된다.
- 다음 페이지 요청에서 `page_size`가 바뀌면 반드시 새 값을 따른다; 나머지 파라미터는 토큰을 받은 호출과 같아야 하고 다르면 `INVALID_ARGUMENT`(권장).
- 응답: 결과 repeated 필드는 첫 필드(권장), `string next_page_token`(권장); 끝이면 반드시 빈 값(끝을 알리는 유일한 방법), 끝이 아니거나 알 수 없으면 반드시 채운다; 반드시 스트리밍이 아니다.
- 토큰은 반드시 불투명한 URL-safe 문자열로 사용자가 파싱할 수 없고, 반드시 리소스 접근 권한을 주지 않는다; 민감하지 않으면 내부 proto를 직렬화해 base64로 만들어도 된다; 만료시켜도 된다(기준 3일).
- `int32 total_size`를 둬도 되고 추정치면 문서화(권장). `int32 skip`을 둬도 된다: 페이지가 아니라 리소스 개수(반드시); 채울 수 없으면 빈 결과로 `200 OK`, 전체 개수를 확실히 넘으면 `next_page_token`을 반드시 비운다.
