- List 등 컬렉션 조회 메서드에 필터링을 둬도 되고, 두면 요청에 `string filter` 하나(권장).
- 문법을 어기거나 스키마에 안 맞는 필터는 `INVALID_ARGUMENT`(권장): 없는 필드, 타입 불일치(`int32 age`에 `age = hello`); enum 값은 반드시 유효한 멤버.
- 리터럴만 쓰면(`42`, `"Hugo"`) 필드 값 어디든 매칭(권장), 특정 필드로 한정해도 되지만 문서화(권장); 공백으로 나열하면 퍼지 AND(`Victor Hugo` ≈ `Victor AND Hugo`).
- 논리 `AND`·`OR`: `OR`이 `AND`보다 먼저 묶인다(`a AND b OR c` = `a AND (b OR c)`); 괄호는 허용하되 요구하지 않는다(권장).
- 부정 `NOT a`와 `-a`: 부정을 지원하면 반드시 둘 다.
- 비교 `=` `!=` `<` `>` `<=` `>=`: 문자열·숫자·timestamp·duration 필드에 제공하고 boolean·enum엔 제공하지 않는다(권장); 필드 이름은 반드시 왼쪽, 오른쪽엔 리터럴과 논리 연산만.
- 값 표기: enum은 이름 문자열(대소문자 구분), boolean은 `true`·`false`, 숫자는 지수 가능(`2.997e9`), duration은 초 + `s`(`20s`, `1.2s`), timestamp는 RFC-3339(`2012-04-21T11:30:00-04:00`).
- 와일드카드: 문자열 같음 비교에 `*`를 지원한다(권장): `a = "*.foo"`.
- 순회 `.`: 중첩 메시지·map·struct(`a.b.c = "foo"`), 리소스 정의의 필드 이름을 쓴다(권장); repeated 필드는 반드시 `.`로 건너지 않는다(`:`와 함께일 때만 예외); 체인 중간 non-primitive가 비어 있으면 불일치; 없는 필드 순회는 `INVALID_ARGUMENT`(권장); map·struct의 미정의 키 처리 방식은 반드시 문서화.
- has `:`(반드시 제공): `r:42`(repeated `r`에 42), `r.foo:42`(`foo`가 42인 원소), `m:foo`(map `m`에 키 `foo`), `m.foo:*`(키 존재), `m.foo:42`(값 42), `r:*`·`m:*`(존재); map·repeated는 미설정과 빈 값이 같다.
- 함수는 `call(arg...)` 꼴로 정의해도 되고 지원 함수는 반드시 문서화; 추가 구조·제한(복잡도 상한 등)을 둬도 되지만 반드시 문서화하고 이 AIP 요구를 반드시 어기지 않는다.
