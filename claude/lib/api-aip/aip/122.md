- 리소스 이름은 API 안에서 반드시 고유하고 앞 `/` 없는 경로 꼴이다: `publishers/123/books/les-miserables`.
- 컬렉션 ID와 리소스 ID를 번갈아 둔다(권장); 구분자는 반드시 `/`, 마지막이 아닌 세그먼트엔 반드시 `/` 없음, 마지막 세그먼트도 `/` 없음(권장).
- DNS 호환 문자(RFC-1123)만 쓰고 리소스 ID에 대문자·URL 이스케이프가 필요한 문자·불필요한 비ASCII를 쓰지 않는다(권장); 유니코드는 반드시 정규화 형식 C(NFC, `~/.claude/lib/api-aip/aip/210.md`).
- 컬렉션 ID는 반드시 간결한 미국 영어 복수형, `camelCase`, `[a-z][a-zA-Z0-9]*`이고 한 리소스 이름 안에서 반드시 고유; `s`를 붙여 없는 단어를 만들지 않는다(반드시).
- 중첩 컬렉션은 부모 접두어를 빼도 된다(`users/{user}/userEvents/{e}` → `users/{user}/events/{e}`); 타입은 `UserEvent` 그대로 두고 `google.api.resource`에 `singular: "userEvent"`, `plural: "userEvents"`를 적으며, 생략은 모든 pattern에 반드시 일관되게.
- 사용자 지정 ID: 허용 형식을 반드시 문서화; RFC-1034(문자·숫자·하이픈, 첫·끝은 문자나 숫자, 최대 63자)와 소문자 `^[a-z]([a-z0-9-]{0,61}[a-z0-9])?$`(권장). 시스템 생성 ID는 형식과 최대 길이를 문서화(권장).
- 리소스는 반드시 `string name`을 노출하고, 리소스 이름이 아닌 필드를 반드시 `name`이라 부르지 않는다(`parent`도 부모 이름 외엔 쓰지 않는다, 권장); 별도 ID 필드(`book_id`)·시스템 생성 `uid`는 둬도 되며 두면 반드시 OUTPUT_ONLY; 튜플·self-link 같은 다른 식별 방식은 반드시 노출하지 않는다; ID 필드는 string(권장).
- 흔한 조회용 별칭을 둬도 되지만 돌려주는 데이터엔 반드시 정식 이름을 쓴다; 다른 API 리소스라 모호할 때만 full resource name(`//{API 서비스 이름}/{relative name}`, 버전 없음)을 쓴다(권장).
- 요청: 단일 리소스 대상(Get, 커스텀 메서드)은 첫 필드 `name` + `resource_reference {type}`(권장); 컬렉션 대상(List, Create)은 첫 필드 `parent` + `resource_reference`(권장), 가능한 부모 타입이 여럿이면 `child_type`(권장).
- 다른 리소스를 가리키는 필드는 리소스 이름을 담는 string, 이름은 대상 메시지의 snake_case(형용사 앞붙임 가능: `dusty_book`), `resource_reference`를 단다(권장); `_name` 접미사는 모호할 때만(`crypto_key_name`), 이름을 못 쓰면 `_id`(`shelf_id`); 리소스 메시지 타입을 그대로 넣지 않는다(권장, 생명주기·권한이 묶인 내부 API와 revision(`~/.claude/lib/api-aip/aip/162.md`)은 예외).
```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book" pattern: "publishers/{publisher}/books/{book}" };
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string shelf = 2 [(google.api.resource_reference) = {type: "library.googleapis.com/Shelf"}];
}
```
