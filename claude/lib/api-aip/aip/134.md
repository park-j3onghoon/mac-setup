```proto
rpc UpdateBook(UpdateBookRequest) returns (Book) {
  option (google.api.http) = {patch: "/v1/{book.name=publishers/*/books/*}" body: "book"};
  option (google.api.method_signature) = "book,update_mask";
}
message UpdateBookRequest {
  Book book = 1 [(google.api.field_behavior) = REQUIRED];
  google.protobuf.FieldMask update_mask = 2;
  bool allow_missing = 3;  // create-or-update를 지원할 때만
}
```
- RPC 이름은 반드시 `Update` + 단수 리소스 이름, 요청은 반드시 `{RPC 이름}Request`, 응답은 반드시 리소스 자체.
- HTTP는 `PATCH`(권장, Google API는 보통 `PUT` 미지원); `body`는 반드시 리소스 필드; URI 변수는 `{resource}.name` 하나(권장); `method_signature`는 `"book,update_mask"`(권장); 리소스 필드는 반드시 있고 REQUIRED(권장).
- `update_mask`는 반드시 이 이름의 `google.protobuf.FieldMask`이고 반드시 선택 필드; 생략되면 반드시 값이 채워진(non-empty) 필드 전부로 본다; `*`(전체 교체, PUT 상당)를 반드시 지원한다. `*`는 클라이언트가 모르는 새 필드까지 덮으니 위험을 감수할 때만 쓴다.
- 응답은 전부 채운 리소스(권장)이고 보내고 마스크에 넣은 필드는 반드시 담는다; 계산이 비싸면 갱신한 필드만 돌려줘도 된다.
- 부작용을 일으키지 않는다(권장); state 필드(`~/.claude/lib/api-aip/aip/216.md`)는 반드시 직접 쓸 수 없다.
- 리소스가 없으면 반드시 `NOT_FOUND`; 단 `allow_missing`이 true면 생성하고 필드 마스크와 무관하게 모든 필드를 적용하며, 이때도 사용자는 반드시 update 권한이 있어야 한다.
- etag를 보내면 서버 값과 같을 때만 반드시 성공, 다르면 반드시 `ABORTED`(`~/.claude/lib/api-aip/aip/154.md`). LRO면 `response_type`은 리소스(`~/.claude/lib/api-aip/aip/151.md`).
- 요청에 뼈대 밖의 필수 필드를 반드시 두지 않고, 다른 AIP가 정하지 않은 선택 필드도 두지 않는다(권장). 오류 확인 순서는 `~/.claude/lib/api-aip/aip/193.md`를 따른다.
