- 오류엔 반드시 `google.rpc.Status`: `int32 code`(반드시 `google.rpc.Code` 값), `string message`(개발자용 디버그 메시지, 영어 권장), `repeated google.protobuf.Any details`.
- `message`는 API 내부를 모르는 사용자를 전제로(반드시) 짧고 해결 가능하게 쓰고(권장) 추가 정보는 `details`에 둔다(권장).
- 모든 오류 응답의 `details`엔 반드시 `ErrorInfo`; detail 타입마다 반드시 한 번만. 표준 payload: `ErrorInfo`, `LocalizedMessage`, `Help`, `BadRequest`, `PreconditionFailure` 등.
- `ErrorInfo.reason`은 반드시 63자 이하 `[A-Z][A-Z0-9_]+[A-Z0-9]`(UPPER_SNAKE_CASE)이고 domain 안에서 고유; `domain`은 반드시 전역 고유(보통 오류를 낸 서비스 이름); 같은 오류엔 반드시 같은 (reason, domain), 논리적으로 다른 오류엔 반드시 다른 쌍.
- `ErrorInfo.metadata`(`map<string, string>`): `message`에 나온 요청별 값(리소스 이름 등)은 반드시 전부 담고, 키는 반드시 64자 이하 `[a-z][a-zA-Z0-9-_]+`, 한 번 노출한 키는 반드시 계속 담는다(값은 비어도 된다).
- `ErrorInfo` 없이 나가던 기존 RPC의 `message`는 반드시 바꾸지 않는다(대신 `LocalizedMessage`), 처음부터 `ErrorInfo`가 있던 RPC는 바꿔도 된다.
- `LocalizedMessage`는 `locale`(BCP 47, `en-US`)과 `message`를 반드시 둘 다 채운다; 문구로 해결이 어려우면 반드시 `Help`(scheme 있는 절대 링크, 공개 서비스면 인증 없이 열림, 둘 다 반드시)를 넣는다.
- 권한을 반드시 존재 여부보다 먼저 확인한다: 권한이 없으면 리소스·부모 존재와 무관하게 `PERMISSION_DENIED`(403), 권한이 있는데 없으면 `NOT_FOUND`(404).
- 부분 오류는 지원하지 않는다(권장); 대량 작업처럼 꼭 필요하면 LRO로 하고 실패 정보는 metadata에 둔다(권장).
