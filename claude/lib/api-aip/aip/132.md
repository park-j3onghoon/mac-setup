```proto
rpc ListBooks(ListBooksRequest) returns (ListBooksResponse) {
  option (google.api.http) = {get: "/v1/{parent=publishers/*}/books"};
  option (google.api.method_signature) = "parent";
}
message ListBooksRequest {
  string parent = 1 [(google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {child_type: "library.googleapis.com/Book"}];
  int32 page_size = 2;
  string page_token = 3;
}
message ListBooksResponse { repeated Book books = 1; string next_page_token = 2; }
```
- RPC 이름은 반드시 `List`로 시작하고 뒤는 복수 리소스 이름(권장); 요청·응답은 반드시 `{RPC 이름}Request`·`{RPC 이름}Response`.
- HTTP는 반드시 `GET`, `body`는 반드시 없음; URI 변수는 `parent` 하나, 나머지는 쿼리 파라미터(권장); `method_signature`는 `"parent"` 하나, 최상위 리소스면 없거나 `""`(권장).
- 최상위가 아니면 `parent`가 반드시 있고 REQUIRED(권장), 타입을 반드시 밝힌다; `page_size`·`page_token`은 모든 List 요청에 반드시 둔다(규칙은 `~/.claude/lib/api-aip/aip/158.md`).
- 응답엔 리소스 repeated 필드가 반드시 하나, 다른 repeated 필드는 두지 않는다(권장); 리소스는 전부 채운다(권장); `next_page_token`은 반드시 두고 다음 페이지가 있으면 반드시 채운다; `int32`(또는 `int64`) `total_size`를 둬도 된다.
- 필터를 지원해도 되고, 지원하면 `string filter`(권장, 문법은 `~/.claude/lib/api-aip/aip/160.md`).
- 정렬을 지원해도 되고, 지원하면 `string order_by`(권장): 쉼표로 구분한 필드 목록(`"foo,bar"`), 기본 오름차순, 내림차순은 필드 뒤에 ` desc`, 여분 공백은 무시, 하위 필드는 `.`; 순서는 타입의 자연 비교(숫자는 수치, 문자열은 사전순)를 따르고 다르면 문서화(권장).
- soft delete를 지원하면 `bool show_deleted`를 두고 기본으로는 삭제된 리소스를 빼고 돌려준다(권장); soft delete 규칙은 `~/.claude/lib/api-aip/aip/164.md`.
- 요청에 뼈대 밖의 필수 필드를 반드시 두지 않고, 다른 AIP가 정하지 않은 선택 필드도 두지 않는다(권장). 오류 확인 순서는 `~/.claude/lib/api-aip/aip/193.md`를 따른다.
