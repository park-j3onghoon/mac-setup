rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {post: "/v1/{name=publishers/*/books/*}:undelete" body: "*"};
}
message UndeleteBookRequest {
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [(google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {post: "/v1/{name=publishers/*/books/*}:expunge" body: "*"};
  option (google.api.method_signature) = "name";
}

- 실수로 지운 리소스를 되살리는 undelete를 지원해도 된다; 지원하려면 `Delete`는 반드시 삭제 표시만 하고 시스템에서 완전히 지우지 않는다; 그렇게 동작하는 `Delete`는 `google.protobuf.Empty` 대신 갱신된 리소스를 돌려준다(권장).
- soft delete 리소스엔 `delete_time`·`purge_time`(`~/.claude/lib/api-aip/aip/148.md`)을 둘 다 두고(권장), `state` 필드(`~/.claude/lib/api-aip/aip/216.md`)가 있으면 `DELETED` 값을 둔다(권장).
- soft delete 리소스는 `Undelete` 메서드를 제공한다(권장): HTTP는 반드시 `POST`, `body`는 반드시 `"*"`, 응답은 반드시 리소스 자체(`UndeleteBookResponse` 없음)이고 불가능하지 않으면 전부 채운다(권장).
- `Undelete` 요청엔 리소스 이름 필드를 반드시 두고 이름은 `name`(권장), `REQUIRED`(권장, `~/.claude/lib/api-aip/aip/203.md`), `resource_reference`로 참조 리소스 타입을 밝히고(권장) 주석에 리소스 패턴을 적는다(권장); 다른 필수 필드는 반드시 두지 않고, 이 AIP나 다른 AIP가 정한 것 밖의 선택 필드도 두지 않는다(권장).
- undelete가 일반 요청으로 감당하기 어려울 만큼 오래 걸리면 장기 실행 작업(long-running operation, LRO, `~/.claude/lib/api-aip/aip/151.md`)을 쓴다(권장): 응답은 반드시 리소스로 귀결되는 `google.longrunning.Operation`, `response_type`은 반드시 리소스(LRO가 아니었다면 돌려줬을 타입), `response_type`·`metadata_type`은 반드시 둘 다 지정.
- soft delete 리소스는 즉시 영구 삭제하는 `Expunge` 커스텀 메서드를 둬도 된다; 대상은 `CREATING`·`READY`·`SOFT_DELETED`(`delete_time`이 있는) 상태의 리소스다.
- `Expunge`의 URI는 반드시 `:expunge` 접미사의 커스텀 메서드, HTTP는 반드시 `POST`, `body`는 반드시 `"*"`, 응답은 반드시 `google.protobuf.Empty`나 `google.longrunning.Operation`; 오래 걸리면 LRO(`~/.claude/lib/api-aip/aip/151.md`)여도 된다(AIP 예시는 `response_type: "google.protobuf.Empty"`, `metadata_type: "OperationMetadata"`); 요청은 반드시 지울 리소스를 이름으로 가리키고 다른 요청 필드는 두지 않는다(권장).
- soft delete된 리소스는 기본으로 `List`(`~/.claude/lib/api-aip/aip/132.md`) 응답에 넣지 않고(권장, `bool show_deleted`가 `true`일 때만 넣는다), `Get`(`~/.claude/lib/api-aip/aip/131.md`)은 `NOT_FOUND` 대신 그 리소스를 돌려준다(권장).
- 영구 삭제(purge) 전략은 합리적인 것을 골라도 된다(30일 같은 기간 뒤 자동 purge, 사용자가 만료 시각 지정(`~/.claude/lib/api-aip/aip/214.md`), 무기한 보존); 어느 전략이든 soft delete된 리소스가 언제 완전히 지워지는지 문서화한다(권장).
- 권한이 없으면 리소스 존재 여부와 무관하게 반드시 `PERMISSION_DENIED`(HTTP 403); 권한 확인은 반드시 존재 확인보다 먼저; 권한은 있는데 리소스가 없으면(만든 적 없거나 이미 expunge됨) 반드시 `NOT_FOUND`(HTTP 404).
- 이미 삭제된 리소스에 soft `Delete`를 부르면 `allow_missing`이 `true`일 때 반드시 성공, `false`면 `NOT_FOUND`(HTTP 404, 권장); 삭제되지 않은 리소스에 `Undelete`를 부르면 반드시 `ALREADY_EXISTS`(HTTP 409).
- `Expunge` 대상이 없으면(만든 적 없거나 이미 expunge됨) 반드시 `NOT_FOUND`(HTTP 404), 있지만 ready·soft-deleted 상태가 아니면 반드시 `FAILED_PRECONDITION`(HTTP 400); 표준 권한 오류(`PERMISSION_DENIED`)도 적용되며, 일반 삭제 권한과 별개인 명시적 expunge 권한(`<service>.<resource>.expunge` 등)을 반드시 요구한다.
