- API 문서(API 레퍼런스·블로그 글·마케팅 문서·과금 설명 등)의 "문자(character)"는 반드시 유니코드 코드 포인트로 정의한다.
- API 주석에 적는 문자열 필드 길이 제한은 전부 반드시 이 문자(코드 포인트) 단위로 재고 강제한다; 그 아래 바이트 상한은 `4 * 문자 수`(4바이트 UTF-8 문자만 쓸 때만 닿는다)이고, 문자 단위 제한을 지원하는 DB(Spanner 등)면 이 바이트 요구는 저장 계층이 처리한다고 봐도 된다.
- 과금·쿼터 단위는 코드 포인트나 UTF-8 바이트 중 무엇을 써도 된다; API가 정하지 않으면 과금 단위는 문자로 본다(바이트당이 아니라 문자당 $0.01).
- 고유 식별자로 쓰는 문자열은 입력을 ASCII(보통 문자·숫자·하이픈·밑줄, `[a-zA-Z][a-zA-Z0-9_-]*`)로 제한한다(권장); 모든 유니코드를 허용하기로 하면 정규화 형식 C(Normalization Form C, NFC)가 아닌 입력은 반드시 거절한다.
- 고유 식별자는 숫자로 시작하지 않는다(권장, 숫자 접두어는 Google이 생성한 ID용으로 예약); 최대 길이는 64자(권장, 필요하면 늘려도 된다); 리소스 ID 세그먼트 권고는 `~/.claude/lib/api-aip/aip/122.md`.
- 유니코드 값은 늘 NFC로 정규화해 저장한다(권장); 고유 식별자는 반드시 늘 NFC로 저장한다.
- 고유 식별(`name`, `id`, `parent` 등)에 쓰는 값은 고유성 검사 전에 반드시 NFC로 정규화한다; NFC가 같은 두 바이트열은 반드시 같은 값으로 다룬다(들어온 문자열을 NFC로 바꾸거나 NFC가 아닌 식별자를 거절); 바이트 표현 그대로 구분해야 하는 값은 `string`이 아니라 `bytes` 타입의 몫이다.
