# 스킬·모듈 작성 규칙

스킬(SKILL.md)과 하위 모듈(lib, 스킬 안 .md·.html 틀)을 쓰거나 고칠 때 줄마다 아래 규칙을 따른다.

## 문장

1. 줄마다 "어떤 경우에 무엇을 한다", 출력 형식, 완료 조건, 명령, 경로, 짧은 예시 중 하나로 쓴다. 모델이 아는 이유·개념 정의·성격 설명·사용자 경향 문장은 지우고, 적용 범위를 정하는 이유는 조건절로 바꾼다.
2. 실패 구간·증상·에러 문구·잘못된 형태처럼 이 환경에서만 아는 사실은 남기고, 인과 연결어(때문에·이므로·so)만 빼서 사실 문장으로 쓴다. 설명하는 법을 정하는 규칙과 `>` 예시 문답은 지시로 보고 남긴다.
3. 여러 규칙이 기대는 원칙은 그 묶음 색인(claude/lib/coding/index.md, private/claude/lib/security/index.md)의 원칙 절에 "원칙: 행동" 한 줄로만 둔다. 판정 기준 카탈로그(plan-review ref-*.md)도 같은 기준을 따른다.
4. 강조어(반드시·특히·IMPORTANT)와 장식 기호(굵게·기울임·「」·★·이모지·①ⓐ·§), 프런트매터·코드 블록 밖 가로줄 `---`를 지운다. 순서는 화살표나 번호 목록으로, 다른 절과 다른 파일의 단계는 "X 절" 이름으로 가리키고, "N단계"는 같은 파일의 번호 단계에만 쓴다. 범위를 정하는 "항상", 출력 표기(✅·⚠️·CRITICAL), 정의해서 쓰는 등급 기호(plan-review ref-test.md의 ★)는 남긴다.
5. 한 규칙 묶음 안에서 한 개념은 한 말로 쓴다. 영어 병기·풀이 괄호·약어 라벨·새로 지은 이름표 대신 원어 하나나 하는 일을 담은 한국어를 쓰되 코드에 이름이 있는 개념(식별자·언어 키워드·라이브러리·테스트 API)은 원어로 쓰고(타입 단언 대신 type assertion), 제목은 한글만(이름이 핵심이면 영어만) 쓴다. 한 규칙 묶음 안에서 한 단어는 한 뜻으로 쓴다. 출력 틀·코드 블록 안 글자는 이 규칙으로 바꾸지 않는다.
6. 라벨 따옴표, 경로 없는 출처 번호와 출처 꼬리표, 빈도 주석, 날짜·커밋·번복 이력 괄호, 사용자 발언 인용, 제목의 `(상세)`를 지운다. 따옴표는 그대로 쓸 문구(출력·질문·문장 꼴)와 찾을 문자열에만 두고, 내용 항목·상태 이름에 두른 따옴표는 지운다. 출력 틀 안에서 고를 수 있는 절을 표시하는 `<!-- (선택) -->`은 남긴다.
7. 예시는 맞는 예만 둔다. 틀린 형태가 리뷰의 탐지 단서면(.html 수식어, sleep, form.state.values 직접 읽기, 보안 코드 예) 그 형태가 드러나게 남긴다. 예시도 그 파일의 규칙(이름·주석 언어·어투·표기)을 지키고, 실제 코드에서 딴 예시는 지금 동작에 맞추며 이름은 비공개 파일이면 지금 이름, 공개 파일이면 규칙 23의 일반 이름으로 쓴다.
8. 부정형 지시는 지킬 상태를 쓰는 긍정문으로 바꾸고, 원래 항목이 모두 덮이는지 대조한다. 위치는 있는 곳만 쓴다. 같은 뜻의 긍정 지시가 이미 있으면 부정문을 지우고 막을 명령 이름은 남긴다. 서술어가 거부·견제·자제·회피·지양·불필요인 지시도 부정형으로 보고 "X 대신 Y"나 리뷰 기준의 "X는 지적" 꼴로 쓰며, 지적할 형태를 이름 짓는 "불필요한 X" 명사구는 둔다.
9. 흐린 말과 판정할 수 없는 지시(거의·적절·가능하면·고려한다)는 판정할 수 있는 조건과 행동으로 쓰고, 비교와 기준은 수치로 쓴다. 기준 숫자에는 세는 법·적용 범위·예외·넘었을 때 할 일을 같은 항목에 적는다. 판정 기준 카탈로그(plan-review ref-*.md, claude/lib/review의 리뷰 기준)의 점검 항목에 든 크기·정도 말(대량·대규모)은 같은 항목이 찾을 형태를 괄호나 화살표로 적었으면 둔다. 새 기준 숫자나 조건이 필요하면 후보와 근거를 보이고 사용자가 정한다.
10. 지워도 행동이 안 바뀌는 문장(같은 말 반복, 앞 예시와 같은 종류를 다시 보이는 예시, 틀이 알아서 하는 일)을 지운다. 종류가 다른 예시를 나열해 적용 범위를 보이면 둔다. 다른 파일 규칙을 베낀 점검표는 지우고 고유 항목만 그 단계 완료 조건으로 옮긴다. 실제로 Read되지 않는 선택 예시 목록과 참고 링크도 지우고, description과 목록의 같은 뜻 표현(동의어·번역)은 하나만 둔다.
11. 이제 사실이 아닌 문장, 안 도는 분기, 낡은 예시, 없는 파일·절·스킬을 부르는 문장을 고치거나 지운다. 줄번호·해시·다른 파일의 내용을 세는 개수처럼 바뀌면 틀려지는 값은 파일 경로까지만 쓰고, 같은 파일 안에 나열이 있는 개수는 둔다.
12. 단계가 있는 스킬·모듈은 단계마다 그 단계 산출물로 판정하는 완료 줄을 `→ 완료:`로 두되 그 단계의 분기·지시는 완료 표시 앞에 쓰고, 마지막 완료 줄은 성공한 모습으로 쓴다. 단계가 없는 모듈이 절 끝에 완료 줄을 두면 그 줄도 `→ 완료:`로 쓴다.
13. SKILL.md 본문에는 AI가 실행할 지시와 기본 동작을 바꾸는 핵심 제약만 둔다. 본문 첫머리 요약 줄, 사람용 머리말·요약 표, 형제 스킬과의 경계 문장, 자주 나온 질문은 지우고, 사람용 설명은 description과 README 한 줄로 둔다. 프런트매터는 name, description, disable-model-invocation: true와 필요할 때 argument-hint(값은 큰따옴표), allowed-tools(전역 허용 밖 도구만)로 둔다.
14. claude/lib/coding·claude/lib/review와 private/claude/lib의 `*-rules.md`·`coding-rules-*.md` 규칙 문장은 경계 데이터를 DTO(프런트 요청 본문은 request body)로, 떼어 낸 단계는 함수·추출한 함수·service·util로 부르고, strategy는 전략 패턴을 구현할 때만 쓴다.
15. 보안 점검 기준(private/claude/lib/security, claude/lib/review/security-gate.md)의 항목은 "~하는가" 질문이나 "~는 발견이다" 판정 문장으로 쓰고, 지킬 상태를 적는 기준 문장(~한다)과 리뷰어가 할 일을 적는 절차 문장(~인지 본다)은 그 꼴로 둔다.

## 배치와 포인터

16. 쓰는 곳이 하나면 그 스킬 디렉터리(그 단계)에, 둘 이상이면 claude/lib(회사 내용이면 private/claude/lib)에 둔다. 두 스킬이 같은 단계를 가지면 그 절차 전체를 lib 모듈 하나로 뽑고, 스킬에는 Read 줄과 고유 단계만 둔다. ~/.claude 최상위 .md는 CLAUDE.md 하나로 둔다.
17. 같은 규칙이 여러 파일에 있으면 한 곳(공개와 비공개가 겹치면 공개 lib)에만 두고 나머지는 포인터로 바꾼다. 같은 상황에 두 답을 주는 규칙은 답 하나로 만든다. 읽는 조건이나 읽는 서브에이전트가 달라 한쪽만 읽히는 사본, 완료 기준인 점검표, 문서 형식 규칙은 남긴다.
18. 공용 모듈 안에서 호출자마다 갈리는 분기와 명령은 호출하는 스킬로 옮긴다. 하위 모듈(lib, 스킬 안 .md)은 내용만 담고, 부르는 스킬 이름·소비자 목록·로드 안내는 읽는 쪽에 둔다.
19. 포인터는 그 모듈을 직접 쓰는 파일마다 "`~/.claude/…` 전체 경로를 Read하고 {할 일}" 평문으로 둔다. 전역으로 로드되는 모듈도 같고, 스킬 안 모듈은 `~/.claude/skills/{스킬}/…`로 쓴다. 포인터에는 경로와 할 일만 쓴다. 설계 개념 이름(DDD 등) 대신 그 내용을 담은 lib 파일 경로를 가리킨다. 같은 파일에서 이미 Read하게 한 모듈이나 index.md 목록으로 읽게 한 모듈을 다시 가리킬 때와, Read 지시가 다른 곳에 있는 모듈의 위치만 알릴 때는 Read 없이 전체 경로와 절 이름을 쓴다.
20. 모든 답에 쓰이는 규칙만 CLAUDE.md에서 전역 import하고, 일부 상황에만 쓰는 규칙은 조건을 적은 포인터로 그때만 Read한다. 상황마다 갈리는 규칙 묶음은 lib/{이름}/index.md(공통 규칙과 "언제 → 어느 모듈" 목록)와 상황 모듈로 나눈다.
21. 서브에이전트가 읽는 기준 파일에서 answer-style과 겹치는 지시는 지우고, 꼭 지킬 것은 출력 형식 칸(`근거: {file:line | 미확인}`)에 둔다. 사람이 읽는 문서(PR·RFC·카드)를 쓰는 스킬은 `~/.claude/lib/document-tone.md`를 가리킨다.
22. claude/lib/coding의 분야 파일에는 언어와 상관없는 결정만 두고, 언어·프레임워크·책(Cosmic Python)의 이름과 모양은 `{분야}-{스택}.md`로 옮긴다. 예시 코드의 문법과 분야 파일 제목이 정한 DBMS(db.md의 MySQL)는 분야 파일에 둔다. 스택 파일은 그 분야에 언어별 규칙이 있을 때만 두고, 분야 파일 첫머리 포인터로 그 언어일 때만 Read한다. architecture.md에는 층, 의존 방향, 층마다 맡는 일, 관례만 둔다.
23. 공개 claude/ 파일과 mac-setup 커밋 메시지는 회사 이름, 사내 서비스·레포 이름, 이슈 키, 사내 코드에 그대로 있는 이름(낱말이 평범한 클래스·함수·필드 이름과 주석 문구도 해당) 대신 일반 표현이나 지은 이름으로 쓰고, 회사 내용은 git 밖 private/에 둔다. 공개 파일에 예시 이름을 새로 쓰면 사내 코드에서 `rg -w`로 찾아 나오는 이름은 다시 짓되, 언어·프레임워크·라이브러리·도구가 정한 이름과 `created_at`·`user_id`·`*_count`·`is_*`처럼 어느 코드베이스에나 있는 꼴은 그대로 쓴다. 공개 파일의 예시 경로는 `{…}`나 `<…>` 자리표시로 쓴다.
24. 모듈·스킬·제목을 옮기거나 이름을 바꾸거나 지우면 같은 커밋에서 그것을 가리키는 포인터·절 이름·index 설명·README 표를 고친다. SKILL.md description을 고치면 같은 커밋에서 최상위 README.md 스킬 표와 버킷 README.md의 그 스킬 줄을 description과 같은 문장으로 고친다.

## 흐름

25. 다음 스킬을 권하는 문장은 investigate 스킬 끝의 "수정이 5개 파일 이상이면 implement 스킬을 권하고 멈춘다" 하나만 둔다. 나머지 스킬은 결과와 경로를 알리고 멈추며, 전제가 안 맞을 때 해야 할 스킬로 되돌려 보내는 문장만 둔다.
