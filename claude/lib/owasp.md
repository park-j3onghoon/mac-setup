# OWASP Top 10 점검 (A01 · A03 · A05 · A07 · A10)

공격자 관점으로 취약점 자체를 보는 모듈이다. 사내 기준 준수(고시·지침·진단 유형)는 `~/.claude/lib/security/`가 본다.

항목마다 발견 / PASS / 해당 없음을 구분해 판정한다. 살펴봤는데 없으면 PASS, 대상 코드와 무관하면 해당 없음이다.

## 증명 방식

source(외부에서 들어오는 값: 요청 파라미터·바디·헤더·업로드·외부 API 응답)에서 sink(권한 판정·쿼리·명령 실행·URL 구성·템플릿 출력)까지 코드로 이어지는 경로를 보인 것만 발견으로 올린다.

- 경로를 코드로 이었으면 `VERIFIED`
- 패턴 매칭까지만 했으면 `UNVERIFIED`
- 중간에 검증·이스케이프·권한 체크가 있으면 그 라인을 인용하고 발견에서 뺀다

## A01 접근 제어

- 인증 데코레이터·미들웨어 없이 열린 라우트. 형제 라우트와 비교해 빠진 것을 찾는다.
- IDOR: 경로·바디의 id를 그대로 조회하고 소유자 확인이 없는 곳. `get(pk=`·`filter(id=` 뒤에 사용자 스코프 조건이 붙는지 본다.
- 권한 판정이 프론트에만 있고 서버에 없는 것.
- 관리자 전용 기능이 역할 확인 없이 노출된 것.

보는 자리: 라우팅 정의, 핸들러 진입부, 권한 클래스.

## A03 인젝션

- SQL: 문자열 포매팅·f-string·concat으로 만든 쿼리, `raw(`·`extra(`·`cursor.execute`에 변수가 섞이는 곳.
- 명령: `subprocess`·`os.system`·`shell=True`에 입력이 들어가는 곳.
- 템플릿·XSS: `mark_safe`·`|safe`·`v-html`·`innerHTML`·`dangerouslySetInnerHTML`.
- 역직렬화: `pickle`·`yaml.load`(Loader 미지정)·`eval`·`exec`.

## A05 보안 설정 오류

- CORS 와일드카드와 credentials 허용이 같이 켜진 것.
- `DEBUG=True`, 상세 에러 페이지가 운영 설정에 남은 것.
- `ALLOWED_HOSTS`·`server_name` 와일드카드.
- 관리 인터페이스(admin·swagger·api-docs·actuator)가 인증 없이 열린 것.
- 기본 자격증명·예제 키가 설정에 남은 것.

## A07 인증 실패

- 로그인 후 세션 재생성이 없어 세션 고정이 가능한 것, 만료가 없는 세션.
- JWT: `exp` 미검증, `alg: none` 허용, 서명 키 하드코딩.
- 비밀번호가 평문이거나 md5·sha1 단독 해시로 저장되는 것.
- 로그인 시도 제한이 없는 것.
- 토큰이 URL 쿼리스트링이나 로그에 실리는 것.

## A10 SSRF

- 사용자 입력으로 URL을 만들어 `requests`·`fetch`·`urlopen`에 넘기는 곳.
- 웹훅 등록, 외부 이미지·문서 가져오기, 리다이렉트 파라미터.
- 스킴·호스트를 허용 목록 없이 그대로 신뢰하는 것.
- 내부망 주소(`169.254.169.254`·`127.0.0.1`·`10.`·`172.16.`·`192.168.`) 차단 여부.

## 출력

```
[CRITICAL|INFO] file:line · 설명 (A0N) VERIFIED|UNVERIFIED
```

시크릿·개인정보로 의심되는 값은 출력에 싣지 않는다. 종류와 위치만 쓴다.
