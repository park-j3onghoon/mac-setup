diff를 아래 카테고리의 관점으로 검증한다. `~/.claude/lib/review/tool/index.md`를 Read하고, 그 목록에서 diff가 쓰는 도구의 모듈을 Read해 도구 이름을 카테고리로 더한다.

## 조용한 실패와 기본값

- 예외가 나지 않는 코드(순수 계산, 상수 조회)를 감싼 예외 처리는 지적하고 지우게 한다.
- 입력(요청, 메시지, 파일)에 필수 값이 빠졌는데 코드가 기본값을 채워 진행하면 지적하고, 거절하거나 에러로 멈추게 한다.
- 대상 목록이 비었을 때 코드가 전체를 대상으로 처리하면 지적하고, 아무것도 하지 않거나 거절하게 한다.
- 구분자로 나눈 문자열 목록을 쓰는 코드가 빈 입력에서 나오는 `[""]`를 값 하나로 처리하면 지적한다.
- 필수 enum 필드가 빈 값(`''`, `UNSPECIFIED`)을 받고도 검증을 통과하면 지적한다.
- 범위의 최솟값과 최댓값으로 따로 조회하는 코드가 두 값이 같을 때 같은 조회를 되풀이하면 지적하고 한 번만 조회하게 한다.
- 판정 함수가 데이터 없음과 불일치를 같은 거짓 값으로 돌려주면 지적하고, 결과를 enum(matched, mismatched, skipped)이나 (bool, 이유) 쌍으로 나누게 한다.
- 컬럼을 더는 쓰지 않게 바꾸면, 그 컬럼에 이미 쌓인 값을 읽던 조회(옛 컬럼 값을 더하는 합계)가 계속 그 값을 읽는지 보고 빠지면 지적한다.

## 트랜잭션·동시성·순서

- 커밋 뒤에 다른 시스템을 부르는 코드가 그 호출이 실패해도 성공 응답을 돌려주면 지적하고, 보낼 요청을 같은 트랜잭션 안 테이블에 남겨 커밋 뒤 따로 보내는 outbox나 먼저 만든 리소스를 지우는 보상 처리로 바꾸게 한다.
- 행을 조회한 결과로 그 행을 지우는 코드(SELECT 뒤 DELETE)는 지적하고, 조건을 건 DELETE 한 번이나 잠금으로 바꾸게 한다.
- 여러 개 가운데 하나를 고르는 코드가 순서가 정해지지 않은 첫 원소를 쓰거나 값이 겹칠 수 있는 컬럼 하나로만 정렬하면(`ORDER BY created_at`) 지적하고, 정렬에 보조 키(id)를 더하게 한다.
- 캐시·락 키의 단위(계정, 사용자, 세션)를 새로 정하거나 바꾸면, 한 계정을 여러 사람이 함께 쓸 때 남의 캐시를 읽거나 남의 락에 막히는지 보고 그러면 지적한다.

## 금액

- 금액을 계산하는 코드에 소수점 자릿수, 반올림 방식, 통화가 정해져 있지 않으면 지적한다.
- 환율을 바꾸는 코드가 그 환율로 계산한 금액을 다시 계산하지 않거나, 환율을 저장하기 전에 다시 계산하면 지적한다.

## 기존 코드와의 일관성

- diff가 새로 만든 함수·플래그·조건식과 같은 일을 하는 기존 함수나 도메인 메서드를 Grep으로 찾아, 있으면 지적하고 그것을 쓰게 한다.
- 같은 꼴로 나란히 있는 설정·분기·목록 항목 가운데 일부만 바꾸거나 새 항목을 더하면, 나머지 항목에도 같은 변경이 필요한지 보고 빠졌으면 지적한다.
- diff 때문에 쓰는 곳이 없어진 함수·필드는 deprecated 표시 대신 같은 PR에서 지우게 한다.

## 데이터베이스·스키마

- 새 쿼리의 조건이 복합 인덱스의 첫 컬럼을 쓰지 않으면 지적한다.
- 새 복합 인덱스가 값 종류가 적은 컬럼(상태, 참거짓)을 앞에 두면 지적한다.
- 지울 행 수가 정해지지 않은 DELETE(조건만 건 DELETE 한 번)는 지적하고, 정해진 크기씩 나눠 지우게 한다.
- ORM의 DB 연결 설정(풀 크기, 연결 유지 시간, 타임아웃)을 바꾸면 지적하고, 그 연결을 쓰는 API에서 확인한 결과를 PR에 적게 한다.
- DB enum 컬럼이 받는 값을 코드에 더했는데 마이그레이션이 없으면 지적한다.
- API 응답이나 저장하는 JSON을 타입 없는 dict·map으로 바로 내보내면 지적하고, 필드 타입이 있는 스키마(DTO)로 바꾸게 한다.
- 구분 필드 없는 union 타입은 지적하고 구분 필드가 있는 union으로 바꾸게 한다.

## 로그·메트릭

- 루프 안에서 항목마다 남기는 debug 로그는 지적하고 머지 전에 지우게 한다.
- info 로그에 `[DEBUG]` 같은 접두어가 있으면 지적하고, 테스트용이면 지우고 아니면 debug 레벨로 바꾸게 한다.
- 기존 로그에 샘플링이 걸려 있으면 같은 종류의 로그를 새로 남기는 곳에도 같은 샘플링을 걸었는지 보고, 빠졌으면 지적한다.
- 한 사건을 여러 줄 로그로 나눠 남기면 지적하고, 한 줄에 필드로 묶어 요청 추적 id(`correlation_id`)를 넣게 한다.
- 새 메트릭이 같은 대상을 재는 기존 메트릭과 다른 이름이나 다른 단어 순서(기존 `daily_total`, 새 `total_daily`)를 쓰면 지적한다.
- 새 메트릭이 기존 메트릭과 같은 값을 재면 지적한다.
- 새 메트릭을 볼 알람이나 대시보드가 PR에 없으면 지적한다.
- 메트릭 라벨에 사용자 id·요청 id처럼 값 종류가 끝없이 늘어나는 값을 넣으면 지적한다.
- 새로 만든 배치, consumer, 다른 시스템 호출에 성공·실패 수를 재는 메트릭이 없으면 지적한다.

## 설정과 생성 파일

- 환경(dev, staging, prod)마다 달라야 하는 값을 코드에 상수로 넣으면 지적하고 환경 변수나 설정 파일로 옮기게 한다.
- 정의만 있고 읽는 곳이 없는 환경 변수는 지우게 한다.
- 새 재시도 코드의 횟수·간격이 저장소의 기존 재시도 설정과 다르면 지적한다.
- 테스트에서만 쓰는 패키지를 운영 의존성에 더하면 지적하고, 개발용 의존성(개발용 requirements 파일, `devDependencies`)으로 옮기게 한다.
- 도구가 만든 산출물 디렉터리(`.playwright-mcp`)가 diff에 들어 있으면 지적하고 `.gitignore`에 더하게 한다.
- 도구가 만들고 업데이트 때 다시 쓰는 파일(`{도구} init`이 만든 템플릿)을 손으로 고치면 지적하고, 도구 설정이나 따로 둔 파일에서 바꾸게 한다.
- AGENTS.md·CLAUDE.md가 되돌릴 수 없는 명령(`rm -rf`, `git push --force`, 운영 DB 쓰기)을 실행하게 하면 지적한다.
- diff의 JSON 파일이 파싱되지 않으면 오류 위치를 줄 번호로 짚어 지적한다.

## 배포

- 다른 서비스의 변경이 있어야 동작하는 diff면, 그 서비스의 PR과 배포 순서(서버 → 게이트웨이 → 화면)가 PR 본문에 있는지 보고 없으면 지적한다.
- 공유 API 스펙 패키지의 버전을 바꾸면 스펙 저장소의 짝 PR이 있는지 보고, 없으면 지적한다.
- 여러 유형(상품 종류, 매체 종류)의 동작을 한 번에 바꾸는 diff는 지적하고, 유형별로 나누거나 비율을 정해 차례로 적용하게 한다.
- 배포 설정의 서비스 이름·환경 값이 PR이 바꾸려는 대상과 다르면 지적한다.

## 변경 설명

- PR 본문에 바꾸는 이유 없이 바뀐 파일·함수 나열만 있으면 지적하고 의도를 적게 한다.
- 다른 회사 API를 새로 부르거나 부르는 방식을 바꾸면, 그 회사 정책(호출 한도, 허용 용도)을 확인한 근거가 PR에 있는지 보고 없으면 지적한다.
- 쓰이지 않는 코드를 지우는 PR이면, 그 코드를 더한 PR에 이 PR 링크를 코멘트로 남기게 한다.

## 테스트

- 집계 코드를 바꾸면 빈 입력과 기간 경계(월 합계가 일 합계의 합과 같은지)를 확인하는 테스트가 있는지 보고, 없으면 지적한다.
- 테스트 이름이나 docstring이 약속한 결과를 assert가 확인하지 않고 호출 여부만 확인하면 지적한다.
- 테스트가 결과를 인덱스(`result[0]`)로 꺼내 확인하면 지적하고 id로 찾게 한다.
- 테스트 형식(함수별 테스트, 표 기반 테스트)은 그 파일이 이미 쓰는 형식을 따르게 한다.

## 데이터 분석·머신러닝

- 같은 피처를 애플리케이션 코드와 SQL 두 곳에서 계산하면, 두 결과가 같은지 확인하는 테스트나 쿼리가 있는지 보고 없으면 지적한다.
- 상위 K개나 임계값으로 거르는 평가 코드는, 대상이 K개보다 적을 때 빼는지 넣는지를 코드나 테스트가 정하고 있는지 보고 아니면 지적한다.
- 코드에 넣은 임계값·가중치 숫자에 정한 근거(실험 결과, 문서 링크)가 주석이나 PR에 없으면 지적한다.

## 코드 위생

- 주석 처리한 코드는 지적하고 지우게 한다.
- diff가 바꾼 코드와 맞지 않게 된 주석이 남아 있으면 지적한다.
- base 브랜치에 이미 들어간 코드를 PR이 다시 더하면 지적하고 PR에서 빼게 한다.

## 성능

- 루프 안에서 매번 같은 값을 계산하면 지적하고 루프 밖으로 옮기게 한다.
- 메모리에서 정렬·필터하는 목록이나 범위 조회의 건수 상한이 코드에 없으면, 운영에서 들어올 최대 건수를 묻는 지적을 한다.
- 페이지를 넘길 때마다 같은 집계를 다시 계산하면 지적하고, 서버가 한 번 계산해 돌려주게 한다.

## 변경 이력·과거 리뷰

- 변경된 줄의 원래 의도를 `git blame`과 `git log -L <시작>,<끝>:<파일>`로 거슬러 확인한다. 이번 변경이 그 의도를 되돌리거나 예전에 고친 버그를 다시 들이면 지적한다. 근거는 그 커밋의 해시와 제목이다.
- 같은 파일을 건드린 최근 PR을 `git log -n 10 --format='%h %s' -- <파일>`로 찾는다(커밋 제목의 `(#번호)`). 그 PR의 리뷰 코멘트를 `gh pr view <번호> --comments`와 `gh api repos/{owner}/{repo}/pulls/<번호>/comments`로 읽고, 그때 지적된 문제가 이번 diff에도 해당하면 그 PR 링크와 함께 지적한다.

## 출력 형식

카테고리마다 발견이 있으면 `### {카테고리}: N건`과 `- [CRITICAL/INFO] file:line · 설명`을, 발견이 없으면 `### {카테고리}: PASS`나 `### {카테고리}: 해당 없음`을 쓴다.
