# 보안 게이트 (레벨 1, 매번)

diff 안에 트리거가 새로 생겼을 때만 판정하는 여섯 항목이다. 트리거가 없으면 `해당 없음` 한 줄로 끝낸다. 코드베이스 전체 상태를 봐야 하는 점검(접속기록 정책·세션 만료·TLS·의존성)은 여기 없고, 더 깊은 점검은 보안 서브에이전트 몫이다.

| 트리거 (diff에 새로 생긴 것) | 판정 |
|---|---|
| 핸들러·엔드포인트·RPC 메서드 | 인증(로그인 여부)만 보고 인가를 빠뜨렸는가. 경로·바디의 식별자(`organization_id`·`user_id`)를 조회 키로 쓰기 전에 요청자가 그 자원에 권한이 있는지 서버에서 판단하는가. 화면에서 버튼을 감춘 것은 접근통제가 아니다 |
| 문자열 리터럴 | 키·토큰·비밀번호·접속정보가 값으로 들어왔는가. 암호화 코드면 IV가 상수인가, ECB 모드인가 |
| 로그 문장·에러 응답·직렬화 필드 | 요청/응답 본문을 통째로 남기는가. 운영 에러 응답에 스택트레이스·쿼리·`str(e)`가 실리는가. 화면이 안 쓰는 내부 필드가 응답에 실리는가 |
| 모델 필드·컬럼·DTO | 비밀번호·고유식별번호·계좌번호·카드번호·생체정보가 새 필드로 들어오면 저장 형태를 확인한다(비밀번호는 일방향, 나머지는 암호화) |
| raw SQL·셸 명령 | 문자열 보간(`f"..."`, `.format()`, `+`)으로 쿼리·명령을 조립하는가. 파라미터 바인딩과 인자 배열(`shell=False`)만 허용 |
| 공유 상태 갱신 | 락 없는 동시 접근, non-idempotent 연산의 이중 실행 |

발견은 `[CRITICAL|INFO] file:line · 설명`으로 내되, 시크릿으로 의심되는 값 자체는 출력에 싣지 않는다(종류와 위치만).
