diff에서 문제 지점을 찾아 이슈 리포트 하나로 모은다. 입력은 diff 파일 경로, 출처가 명시된 의도, 리뷰할 코드가 체크아웃된 대상 경로다. 사용자가 명시적으로 승인한 최신 결정을 의도에 반영하고, 그 밖에는 PR 제목·본문(범위 모드는 커밋 메시지)을 기준으로 삼는다.

`~/.claude/lib/coding/load-rules.md`를 Read하고 대상 경로·diff의 변경 범위·연결된 계획으로 규칙을 적재한다. 모은 규칙과 최신 승인 출처를 의도에 포함한다.

## 1. 스코프 체크

의도와 diff가 실제로 하는 일을 비교해 적는다. 최신 승인 내용과 PR 설명이 다르면 문서 불일치로 분리해 적고, 오래된 설명에 맞추려고 승인된 코드 변경을 되돌리지 않는다.

```
Scope Check: [CLEAN / DRIFT / MISSING]
의도: <최신 승인 내용 또는 PR·커밋이 말하는 것과 그 출처 1줄>
실제: <diff가 실제로 하는 것 1줄>
```

diff에서 돈 계산·권한·데이터 변경·외부 호출처럼 틀리면 비싼 곳을 `파일:라인`으로 골라 먼저 볼 곳 목록을 만든다. 목록에 돈 계산이나 권한 항목이 있으면 `Risk: HIGH (돈 계산 · 파일:라인)`처럼, 없으면 `Risk: NORMAL`로 한 줄을 남긴다.

→ 완료: Scope Check 세 줄과 먼저 볼 곳 목록, Risk 한 줄이 있다.

## 2. 보안 레벨

`~/.claude/lib/security/index.md`가 있으면 Read하고 그 파일의 레벨 판정 절 패턴을 입력 diff에 대고, 없으면 레벨 1이다. `Security level: N (트리거: ...)` 한 줄을 남긴다.

→ 완료: `Security level: N (트리거: ...)` 한 줄이 있다.

## 3. 서브에이전트 병렬 리뷰

diff가 아래 조건을 모두 만족하면 리뷰어를 띄우는 대신 빠른 점검을 직접 한다. 호출한 쪽이 병렬 리뷰를 정했으면 빠른 점검 없이 병렬 리뷰로 간다.

- diff 파일에 삭제 줄(`-`)이 없고 추가 줄(`+`) 수가 50 미만이다.
- 추가 줄이 모두 같은 파일에 이미 있는 항목과 같은 꼴의 등록·설정 항목이다(스케줄러 작업 하나, 설정 키 하나처럼). 함수·클래스·조건문·반복문·쿼리·API 경로·proto·이벤트·DB 스키마·enum 값은 이 꼴에 들지 않는다.
- Risk가 NORMAL이고 보안 레벨이 1이다.
- 추가한 항목이 가리키는 코드(부르는 커맨드·함수, 읽는 코드)가 기본 브랜치에 머지돼 있다.

빠른 점검은 아래 다섯 문항에 근거(`file:line`, 명령과 출력)를 붙여 답하고 `~/.claude/lib/review/security-gate.md`의 항목을 판정한다. 답이 문제를 보이면 그 근거로 발견을 낸다. 근거를 찾지 못한 문항이 있으면 빠른 점검을 멈추고 병렬 리뷰로 간다.

1. 가리키는 코드가 그 항목이 쓰일 환경에 배포돼 있고, 넘기는 인자와 키 이름이 그 정의와 맞는가
2. 같은 파일의 형제 항목과 인자·기본값·실패 알림·이름 꼴이 같은가. 다르면 의도에 그 이유가 있는가
3. 새 항목이 실패하면 함께 멈추거나 실패로 보이는 것(같은 묶음의 다른 항목, 레포 안에서 그 묶음을 기다리는 소비자)이 있는가
4. 재시도·재실행·동시 실행의 결과가 한 번 실행한 결과와 같은가
5. 배포 뒤 첫 실행이 만들거나 바꾸거나 보내는 것과 그 범위(건수나 상한)는 무엇인가

병렬 리뷰는 아래 기준 파일마다 리뷰어 하나씩, 한 메시지에서 동시에 띄운다. 추가 줄 수가 200 미만이고 보안 레벨이 1이고 Risk가 NORMAL이면 리뷰어 하나가 코드 공통·언어별·관점 기준 파일을 모두 맡는다. 호출한 쪽이 더하는 서브에이전트도 같은 배치에 띄운다.

- 코드 공통: `~/.claude/lib/review/code.md`
- 언어별: `~/.claude/lib/review/language/index.md`
- 관점: `~/.claude/lib/review/perspectives.md`
- 보안: 레벨이 2 이상일 때만. `~/.claude/lib/security/index.md`의 레벨표가 정한 모듈 전부

프롬프트마다 넣을 것:

1. diff 파일 경로 전부, 기준 커밋·대상 커밋, 의도 요약, 먼저 볼 곳 목록, 대상 경로. diff는 전달받은 파일을 읽고 대상 커밋의 코드로 확인한다. 스코프 체크 절과 빠른 점검에서 직접 확인한 사실이 있으면 근거(`file:line`, 명령과 출력)와 함께 넣고 이 지시를 붙인다: "넘겨받은 사실은 다시 확인하지 않고 근거로 쓴다. 코드가 그 사실과 다르면 그 차이를 발견으로 낸다."
2. 담당 기준 파일의 절대경로와 이 지시: "이 파일을 먼저 Read하고, 항목마다 PASS·해당 없음·발견 중 하나로 판정한다. PASS는 살펴봤는데 발견이 없는 것이고, 해당 없음은 이 diff와 무관한 것이다. 출력은 이 파일의 출력 형식을 따르되, 해당 없음인 카테고리와 항목은 `해당 없음: {이름}, {이름}` 한 줄로 모은다." 기준 파일을 여럿 맡긴 리뷰어에게는 파일마다 따로 판정하고 따로 출력하라고 덧붙인다.
3. 보안 서브에이전트에는 `~/.claude/lib/security/index.md`의 원칙 절과 출력 형식 절을 따르라는 지시.
4. "코드 확인은 대상 경로 안에서 Grep/Read로 한다" + `~/.claude/lib/review/claims.md`를 Read해 옮긴 목록 항목 전부.
5. 규칙 적재에서 모은 규칙 파일(`~/.claude/lib/coding/index.md` 포함)의 절대경로·계획 파일 경로·승인된 판단과 출처, 그리고 이 지시: "이 파일들도 Read하고 같은 규칙과 최신 승인 내용으로 판정한다."
6. 이 지시: "발견마다 근거를 하나 단다: 기준 파일의 항목, 적재한 규칙, 의도와 다른 동작, 실제 값을 넣으면 틀어지는 경우(입력과 결과) 가운데 하나다. 근거가 없으면 내지 않는다. 승인된 판단과 직전 리뷰가 보류·기각·남김으로 닫은 발견은, 그 자리가 이번 diff에서 바뀌지 않았으면 다시 내지 않는다."

→ 완료: 빠른 점검이면 다섯 문항과 `security-gate.md` 항목마다 근거가 붙은 판정이 있고, 병렬 리뷰면 띄운 서브에이전트가 모두 결과를 돌려줬다.

## 4. 다른 AI 교차 검증

아래 기준으로 셋 중 하나를 골라 실행하고, 고른 것과 이유를 한 줄로 알린다. 조건이 여럿 맞으면 아래쪽 항목을 고른다.

- 건너뛰기: 빠른 점검을 했거나, 추가 줄 수 200 미만이고 아래 항목의 조건이 하나도 없음
- diff 리뷰: 추가 줄 수 200 이상 또는 도메인·애플리케이션 레이어 변경
- diff 리뷰 + diff 적대 검증: 새 추상화·레이어 도입, 마이그레이션 동반, 아키텍처 결정

`~/.claude/lib/cross-check.md`를 Read하고, 지금 에이전트에 맞는 절대로 대상 경로에서 실행·회수한다. 같은 diff 파일·기준 커밋·대상 커밋과 적재한 규칙·승인 출처를 전달한다.

→ 완료: 건너뛰기를 골랐다고 알렸거나, 고른 실행의 결과를 회수했거나, 멈추거나 실패한 실행을 자체 적대 점검으로 대체했다고 알렸다.

## 5. 결과 통합

- 같은 이슈를 여러 리뷰어가 잡았으면 하나로 합치고 출처를 `(코드+관점+보안+codex)`처럼 표시한다. 교차 검증 출처는 검증한 AI 이름(codex·claude)으로 쓴다.
- 교차 검증 발견도 같은 목록에 합치고, `~/.claude/lib/cross-check.md`의 결과 취급 절을 따른다.
- 발견의 출처나 출처 수와 관계없이 적재한 규칙과 승인된 판단으로 대조한다. 규칙이 허용하는 코드를 위반으로 본 발견은 남김으로 분류하고 적용 규칙이나 승인 출처를 이유에 적는다.
- 일정을 늘리는 품질 작업은 추천하지 않고, 품질 지적에는 그 작업이 다음 변경을 어떻게 빠르게 하는지 적는다.
- CRITICAL을 위, INFO를 아래로 정렬한다.
- 최종 diff를 설명하는 문서와 PR 제목·본문을 실제로 읽어 불일치를 확인한다(PR이 없는 범위 모드는 문서만 확인한다). 코드 수정 전의 Scope Check만으로 마감하지 않는다. 불일치는 보고하고, 수정 권한이 있을 때만 갱신하며 사용자 작성 부분은 보존한다.
- `~/.claude/lib/review/claims.md`를 Read하고 모든 주장에 적용한다.

→ 완료: 중복이 합쳐지고 심각도순으로 정렬된 이슈 리포트가 있다.
