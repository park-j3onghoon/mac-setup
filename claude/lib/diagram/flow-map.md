# 흐름 지도

틀 `~/.claude/lib/diagram/flow-map.html`을 복사해 `diagram-data` JSON만 채운다.

## 1. 데이터 채우기

- `col`은 단계 순서다: 원천 → 적재 → 가공 → 서비스 → 결과. 화살표는 오른쪽 열로만 간다. `groups`로 열 머리를 시스템 단위로 묶는다.
- 노드 `title`에는 실제 이름(테이블·토픽·함수)을, `tag`에는 소속 시스템을, `sub`에는 저장 형태를 쓴다. `kind`에는 이벤트 로그·테이블·NoSQL·결과물처럼 저장 형태의 갈래를 쓴다.
- `row`는 경로 하나가 가능한 한 한 줄에 놓이게 고르고, 같은 노드로 모이는 것끼리 이웃 줄에 둔다. 한 칸에는 노드 하나만 둔다.
- 화살표 `kind`는 그 단계의 성격이다: 적재·복사, 같은 시스템 안 변환, 다른 시스템에 쓰기, 최종 계산. 주기·조건은 `label`에 쓴다.
- 노드 `detail`에 갱신 주체(잡·DAG 이름과 주기)와 코드 링크를 넣는다.
- 비교할 경로(유형별 경로, 변경 전·후)를 `paths`로 둔다. `target`은 경로의 도착 노드다.
- 변경 전후를 비교하면 없어지는 노드·화살표에 `state: "removed"`, 새로 생기는 것에 `"added"`를 주고, 경로에는 `when: "before"`나 `"after"`를 준다.
- `asOf`에 기준 시점을, `source`에 흐름의 정본(코드·문서) 링크를 넣는다. 색은 `#` 16진수로 쓴다.

→ 완료: 노드마다 `col`·`row`·`title`·`tag`·`kind`가, 화살표마다 `kind`가 채워졌고, `asOf`와 `source`가 들어갔다.

## 2. 저장하고 확인

`~/.claude/lib/diagram/index.md`를 Read하고 생키·흐름 지도 저장 절을 따라 저장하고 브라우저로 연다.

→ 완료: 브라우저에 지도가 떠 있고, 경고 배너가 없고, 채팅에 절대경로가 남았다.
