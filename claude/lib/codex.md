## 도구와 호출

- 스킬의 `/이름`은 Codex에서 `$이름`으로 호출한다. 인자는 사용자 메시지에서 읽고, 하위 모듈은 적힌 `~/.claude/…` 경로로 읽는다.
- Read·Grep·Glob·Bash는 현재 제공된 파일·검색·명령 도구로 수행한다. 명령 도구만 있으면 `exec_command`에서 `rg`·`rg --files`·`cat`을 쓴다. Edit·Write는 `apply_patch`로 수행한다.
- AskUserQuestion은 제공된 질문 도구로 옮긴다. `request_user_input_async`가 있으면 질문을 보내고 답과 무관한 조사만 이어간다. 선택·승인이 필요한 단계는 실제 답을 받은 뒤 수행한다. 질문 도구가 없으면 대화로 묻고 턴을 마친다.
- Agent·Task의 병렬 조사는 제공된 서브에이전트 도구로 수행한다. 동시 실행 한도를 넘으면 배치로 나누고, 서브에이전트 도구가 없으면 같은 담당 기준을 직접 차례로 적용하고 그 사실을 알린다. 서브에이전트에도 이 파일과 담당 기준 파일 경로를 준다.
- Skill 도구를 쓰라는 지시는 해당 스킬의 `SKILL.md`를 읽어 수행한다. `allowed-tools`는 현재 세션의 실제 권한 안에서 해석한다.
- `disable-model-invocation: true`인 스킬은 `agents/openai.yaml`의 `policy.allow_implicit_invocation: false`로 같은 호출 제한을 유지한다. 이미 사용자가 호출한 스킬의 하위 모듈은 그 단계에서 읽는다.
- MCP 도구 이름은 현재 도구 목록과 스키마로 확인한다. 같은 서비스의 Codex 도구를 쓰고, 이름이 다른 도구의 인자는 실제 스키마로 옮긴다. ToolSearch가 없으면 제공된 도구 목록이나 `ALL_TOOLS`에서 이름·설명을 찾는다. 연결되지 않은 서비스는 미확인으로 남기고 연결이 필요한 작업을 알린다.
- `! 명령`은 사용자가 직접 실행할 명령으로 표시한다. 스킬이 사용자 실행을 요구하면 그 실행 결과를 받은 뒤 이어간다.

## 추가 검토

- `simplify`가 제공돼 있으면 그 스킬을 수행한다. 없으면 대상 diff와 적재한 규칙을 전달해 재사용·코드 품질·효율 관점의 서브에이전트 검토를 수행하고, 승인된 범위의 동작을 보존하는 정리만 반영한 뒤 관련 검증을 다시 한다.
- `code-review`가 제공돼 있으면 그 스킬을 수행한다. 없으면 추가 리뷰어에게 같은 diff 파일·기준 커밋·대상 커밋·코드 경로·규칙·승인 출처를 주고 버그·회귀·빠진 테스트를 검토하게 한다. 결과의 출처는 실제 수행한 검토로 적는다.
- 다른 AI 교차 검증은 `~/.claude/lib/cross-check.md`를 Read하고 Codex에서 Claude로 절의 명령을 수행한다.
