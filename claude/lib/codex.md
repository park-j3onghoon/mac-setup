## 도구와 호출

- 스킬의 `/이름`은 Codex에서 `$이름`으로 호출한다. 인자는 사용자 메시지에서 읽고, 하위 모듈은 적힌 `~/.claude/…` 경로로 읽는다.
- Read·Grep·Glob·Bash는 현재 제공된 파일·검색·명령 도구로 수행한다. 명령 도구만 있으면 `exec_command`에서 `rg`·`rg --files`·`cat`을 쓴다. Edit·Write는 `apply_patch`로 수행한다.
- AskUserQuestion은 제공된 질문 도구로 옮긴다. `request_user_input_async`가 있으면 질문을 보내고 답과 무관한 조사만 이어간다. 선택·승인이 필요한 단계는 실제 답을 받은 뒤 수행한다. 질문 도구가 없으면 대화로 묻고 턴을 마친다.
- Agent·Task의 병렬 조사는 제공된 서브에이전트 도구로 수행한다. 동시 실행 한도를 넘으면 배치로 나누고, 서브에이전트 도구가 없으면 같은 담당 기준을 직접 차례로 적용하고 그 사실을 알린다. 서브에이전트에도 이 파일과 담당 기준 파일 경로를 준다.
- Skill 도구를 쓰라는 지시는 해당 스킬의 `SKILL.md`를 읽어 수행한다. `allowed-tools`는 현재 세션의 실제 권한 안에서 해석한다.
- MCP 도구 이름은 현재 도구 목록과 스키마로 확인한다. 같은 서비스의 Codex 도구를 쓰고, 이름이 다른 도구의 인자는 실제 스키마로 옮긴다. ToolSearch가 없으면 제공된 도구 목록이나 `ALL_TOOLS`에서 이름·설명을 찾는다. 연결되지 않은 서비스는 미확인으로 남기고 연결이 필요한 작업을 알린다.
- `! 명령`은 사용자가 직접 실행할 명령으로 표시한다. 스킬이 사용자 실행을 요구하면 그 실행 결과를 받은 뒤 이어간다.

## 사용자 허용과 화면

- 사용자는 2026-11-05에 작업에 필요한 Redash·DataHub의 읽기 전용 조사(메타데이터·스키마·기존 쿼리 조회, SELECT 실행)를 앞으로 재확인 없이 진행하도록 허용했다. 스킬이 요구하는 보조 도구가 없거나 사용할 수 없으면 그 이유만으로 멈추거나 허락을 묻지 말고, 등록된 DataHub 메타데이터 도구와 가드가 붙은 Redash 조회 도구 중 사용 가능한 것으로 근거를 확인하고 계속한다. 이 사용자 지시는 스킬의 보조 도구 필수·재확인 지침보다 우선한다. 테이블·컬럼·기간·파티션은 확인하고, 도구의 접근 제한·예산 차단은 유지한다. 조회 도구가 모두 막힌 경우에만 실제 제한과 미완료 범위를 보고한다.
- 사용자 화면·포커스를 건드리지 않고 백그라운드에서 작업한다. 앱 활성화, 메뉴 클릭·키 입력, 화면에 보이는 메뉴·탭의 조작·탐색·선택, 브라우저 재시작, cmux 포커스 이동·경고 칸 열기는 사용자가 그 화면 조작을 별도로 요청했을 때만 한다. 스킬의 화면 전환·경고 칸 지시보다 이 사용자 지시를 우선한다. 필요한 설정은 가능한 백그라운드 방식으로 직접 처리하고 적용 여부를 검증한다. 화면 조작 없이 진행할 수 없으면 가능한 조사와 준비를 마치고, 완료한 작업과 구분해 제한을 보고한다. 사용자가 2026-11-04에 앞으로도 적용하라고 지시했다.
- `pr-review-report` 결과 열기는 사용자가 2026-11-06에 명시적으로 요청한 포커스 이동 예외다. 리뷰·렌더링·검증을 백그라운드에서 마친 뒤, 완성된 결과 리포트의 브라우저 앱을 활성화하고 현재 세션이 연 결과 탭을 전면으로 가져온다. 실제 연결 도구가 제공하는 탭 선택 기능이나 승인된 macOS 제어 경로를 사용한다.
- Chrome의 Apple Events 자바스크립트 실행이 꺼져 있으면 Codex가 허용 설정을 직접 처리하되 위 백그라운드 제약을 지킨다. 먼저 비활성화를 확인하고, 적용 뒤 실제 JavaScript 실행을 검증한다. 화면 조작이나 브라우저 재시작이 필요한 경우에는 자동으로 수행하지 않고 현재 제한을 보고한다.
- Chrome 브라우저 작업은 Codex에 등록된 `playwright` MCP를 우선 사용한다. 사용자가 승인한 공유 서버 `http://127.0.0.1:8932/mcp`와 기존 Chrome의 `Default` 프로필을 사용한다. 서버는 `--extension --background`로 실행하고 확장의 저장된 토큰으로 재연결한다. AI 세션마다 자신의 작업 탭을 사용하며 다른 세션의 탭은 조작하지 않는다. 로그인 쿠키는 프로필 내에서 공유되므로 로그아웃이나 계정 변경은 다른 세션에도 영향을 준다. 작업 탭은 검증 후 `browser_tabs(action="close")`로 닫고, 사용자에게 남길 결과 탭은 `browser_keep_tab(keep=true)`로 표시한다. 표시한 탭은 세션 종료와 30분 유휴 정리 후에도 남는다. 위 `pr-review-report` 결과 열기에는 포커스 이동 예외를 적용한다. 사용자는 2026-11-05에 승인된 작업에 필요한 Chrome 설정과 연결 허용 작업을 매번 묻지 않고 진행하도록 허용했다. 다른 화면과 포커스 조작에는 위 제한을 유지한다. Chrome이 직접 사용자 확인을 요구하는 경우에는 우회하지 않고 남은 조작을 구체적으로 알린다.
- Playwright는 사용자 launchd 서비스 `local.codex-playwright-performance`의 서버 프로세스 하나를 공유한다. 세션마다 서버를 새로 실행하거나 `--shared-browser-context`를 켜지 않는다. 작업과 대화 종료 때 공유 서버를 중지하지 않는다. 설치와 검증 방법은 `~/git/mac-setup/codex/playwright/README.md`를 따른다. 토큰은 사용자 전용 LaunchAgents 설정에 저장하고 대화, Git, 전체 환경 변수 출력에 노출하지 않는다. Playwright가 등록되지 않은 기존 세션은 현재의 `chrome-devtools` 공유 연결을 그대로 사용할 수 있다. 이 경우 `new_page(background=true)`와 명시적인 `pageId`를 사용하고 작업 탭을 닫는다. 다른 세션이 사용하는 기존 Chrome 공유 프로세스도 종료하지 않는다. 별도의 DevTools 직접 연결을 새로 만들지 않는다.

- 로컬 HTML 리포트를 Playwright로 검증할 때는 해당 파일 디렉토리만 loopback HTTP 서버로 제공한다. 기본 설정의 `file://` 접근 제한을 전역 해제하지 않는다. 검증 후 서버를 닫고, 완성된 로컬 리포트를 사용자에게 보여 줄 때는 위 포커스 이동 예외에 따라 승인된 macOS 파일 열기 경로를 사용할 수 있다.

## 추가 검토

- `simplify`가 제공돼 있으면 그 스킬을 수행한다. 없으면 대상 diff와 적재한 규칙을 전달해 재사용·코드 품질·효율 관점의 서브에이전트 검토를 수행하고, 승인된 범위의 동작을 보존하는 정리만 반영한 뒤 관련 검증을 다시 한다.
- `code-review`가 제공돼 있으면 그 스킬을 수행한다. 없으면 추가 리뷰어에게 같은 diff 파일·기준 커밋·대상 커밋·코드 경로·규칙·승인 출처를 주고 버그·회귀·빠진 테스트를 검토하게 한다. 결과의 출처는 실제 수행한 검토로 적는다.
- 다른 AI 교차 검증은 `~/.claude/lib/cross-check.md`를 Read하고 Codex에서 Claude로 절의 명령을 수행한다.
