# /implement — 계획대로 구현

**tracer bullet** — 레이어를 하나씩 완성하지 않고, 진입점에서 저장소까지 관통하는 얇은 슬라이스를 하나 끝내고 넓힌다.

## 1. 범위 확정

인자가 경로면 그 계획 파일을 Read한다. 인자가 없으면 `~/plans/{repo}/*/plan.md`를 Glob으로 찾아 후보를 보여주고 고르게 한다. 계획 파일이 없으면 대화 맥락에서 무엇을 만들지 정리해 출력하고 승인을 받는다(계획 자체를 새로 설계하지는 않는다 — 설계가 필요하면 `/plan-review`가 먼저다).

계획이 여러 PR로 쪼개져 있으면 이번에 어디까지 할지 확정한다.

→ 완료: 구현할 항목 목록과 이번 범위의 끝이 한 문단으로 적혔고 사용자가 동의했다.

## 2. 안전 모드

`~/.claude/lib/guard.md`를 Read하고, 이번 작업 디렉토리(계획이 가리키는 레포 경로)로 careful·freeze를 건다. 그 문서의 활성화 메시지를 출력한다. 이미 `/guard`가 걸려 있으면 범위만 확인하고 넘어간다.

→ 완료: 위험 명령 경고와 편집 범위가 적용 중이고 사용자가 범위를 봤다.

## 3. 규칙 적재

- `~/.claude/coding-rules.md`를 Read한다. diff가 닿을 스택에 따라 `coding-rules-python.md`·`-frontend.md`·`-db.md`도 Read한다.
- 레포가 payments-api면 `~/.claude/payments-api-rules.md`도 Read한다.
- **API(proto·REST)를 새로 만들거나 기존 엔드포인트를 고치면** `~/example/.claude/lib/api-aip/index.md`를 Read하고 그 문서의 트랙 판정부터 수행한다(파일이 없는 환경이면 건너뛴다).

→ 완료: 이번 변경에 걸리는 규칙 섹션을 뽑아 뒀고, API 변경이면 트랙·컨벤션 4종(엔벨로프·페이지네이션·에러 shape·필드 케이스)이 확정됐다.

## 4. 기존 패턴 확인

만들 구조와 같은 역할을 하는 코드가 이미 있는지 Grep으로 찾는다 — 형제 모듈의 레이어 배치, 네이밍, 에러 타입, 테스트 관행. 기존 패턴과 다르게 가야 하면 그 이유를 한 줄로 적고 사용자에게 확인받는다.

→ 완료: 참고한 형제 파일 경로가 적혔고, 벗어나는 지점은 사용자 동의를 받았다.

## 5. seam 합의

테스트를 어디에 걸지 먼저 정한다. **seam**은 내부를 들여다보지 않고 동작을 관찰할 수 있는 공개 경계다 — usecase `execute`, port, HTTP 엔드포인트. 이번 범위에서 테스트할 seam 목록을 뽑아 사용자에게 확인받는다. 합의되지 않은 seam에는 테스트를 쓰지 않는다.

전부 테스트할 수는 없으므로, 여기서 critical path와 복잡한 분기에 노력을 몰아준다.

→ 완료: 테스트할 seam 목록이 사용자 확인을 받았다.

## 6. 슬라이스 구현

범위를 vertical slice로 나눠 하나씩 끝낸다. 각 슬라이스는 진입점 → usecase → repo → 저장소까지 관통하고, 합의한 seam의 테스트로 닫힌다.

1. **red** — 그 슬라이스의 계약을 테스트로 먼저 쓴다. 실패하는 것을 눈으로 확인한다.
2. **green** — 통과시키는 최소 코드를 쓴다.
3. **refactor** — green 상태에서 구조만 정리한다. 동작 변경과 구조 변경을 한 커밋에 섞지 않는다.

슬라이스 경계는 계획의 항목을 따르고, 하나가 30~40줄 넘는 함수를 만들면 책임 단위로 쪼갠다. 기존에 없던 추상화(공용 헬퍼·새 레이어)는 넣기 전에 묻는다.

→ 완료: 슬라이스마다 red를 본 테스트가 green이고, 계획의 이번 범위 항목이 전부 체크됐다.

## 7. 검증

변경한 모듈의 테스트를 돌리고 출력을 그대로 붙인다. 전체 스위트가 로컬에서 안 도는 레포는 그 사실을 적고 CI를 게이트로 삼는다. 파일을 옮겼거나 import 경로를 바꿨으면 빌드 명령도 돌린다 — 테스트 통과가 빌드 통과를 보장하지 않는다.

→ 완료: 테스트 출력이 붙었고 회귀 0, 파일 이동이 있었다면 빌드도 성공했다.
