# /session-review — 세션 종료 전 개선사항 점검

이번 세션의 대화를 돌아보며, 영구적으로 반영할 개선사항이 있는지 확인하고 사용자에게 제안한다.

## Step 1: 세션 회고

이번 세션에서 있었던 일을 카테고리별로 정리한다:

- **사용자가 수정 요청한 것**: 접근 방식 변경, 규칙 추가/수정
- **반복된 패턴**: 같은 지적을 여러 번 한 것, 같은 질문을 반복한 것
- **새로 알게 된 것**: 사용자 선호, 프로젝트 맥락, 팀 정보
- **불편했던 것**: 워크플로우 병목, 누락된 자동화
- **잘 작동한 것**: 사용자가 긍정적으로 반응한 접근 방식

## Step 2: 개선사항 분류

아래 각 영역에 대해 반영할 내용이 있는지 판단한다.

### 2a: CLAUDE.md
- **전역** (`~/.claude/CLAUDE.md`): 프로젝트 무관한 개인 선호, 범용 규칙
- **프로젝트** (`{project}/CLAUDE.md`): 특정 프로젝트 전용 규칙
- 확인 사항: 기존 규칙과 충돌하지 않는지, 이미 있는 내용이 아닌지

### 2b: 스킬
- **신규 스킬**: 반복적으로 수행한 워크플로우가 스킬로 만들 만한지
- **기존 스킬 수정**: 이번 세션에서 스킬 동작에 불만/개선이 있었는지
- **스킬 삭제**: 더 이상 쓰지 않는 스킬이 언급됐는지

### 2c: 메모리
- **user**: 사용자 역할, 선호, 지식 수준에 대해 새로 알게 된 것
- **feedback**: 사용자가 교정하거나 확인한 접근 방식
- **project**: 프로젝트 상태, 목표, 제약사항 변화
- **reference**: 새로 알게 된 외부 리소스 위치
- 확인 사항: 기존 메모리와 중복/충돌 여부 (`MEMORY.md` 확인)

### 2d: 위생 검사 필요 여부
- 이번 세션에서 self-improvement가 실행됐는지 확인
- 최근 5회 작업(메모리에서 확인)에서 self-improvement가 3회 이상이면:
  > "/hygiene(위생 검사)를 실행하여 축적된 규칙을 정리할 때가 됐습니다. 실행할까요?"

### 2e: 기타
- **hooks/설정**: 자동화할 만한 반복 작업이 있었는지
- **에이전트 설정**: 서브에이전트 구성에 개선할 점이 있었는지

## Step 3: 제안 목록 작성

발견한 개선사항을 **하나의 목록**으로 정리하여 사용자에게 보여준다.

```
## 이번 세션 개선사항 제안

### CLAUDE.md
1. [전역/프로젝트] 내용 요약 — 근거: 세션에서 X 때문에

### 스킬
2. [신규/수정/삭제] 스킬명 — 내용 요약

### 메모리
3. [user/feedback/project/reference] 내용 요약

### 기타
4. 내용 요약

---
반영할 항목 번호를 알려주세요 (예: 1,3,4 / 전부 / 없음)
```

**반영할 내용이 없으면**: "이번 세션에서 반영할 개선사항이 없습니다." 한 줄로 끝낸다.

## Step 4: 승인된 항목 반영

사용자가 선택한 항목만 반영한다. 각 반영 후 1줄 요약:
`[완료] {항목번호}. {내용}`

## 판단 기준

반영할 만한 것:
- 사용자가 **명시적으로 교정**한 것 ("그렇게 하지 마", "이렇게 해")
- **2회 이상 반복**된 패턴
- 사용자가 **긍정 확인**한 비자명한 접근 방식

반영하지 않을 것:
- 이번 세션에서만 유효한 일시적 맥락
- 이미 CLAUDE.md나 메모리에 있는 내용
- 코드/git에서 직접 확인 가능한 것

## Step 5: 세션 종료

모든 반영이 완료되면 아래를 출력하고 **더 이상 응답하지 않는다**:

```
세션 정리 완료. /exit로 종료해주세요.
```
