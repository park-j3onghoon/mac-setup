# /session-review — 세션 자가개선

이번 세션의 lesson을 각각 한 저장소로 route하고, 사용자가 승인한 것만 반영한 뒤 세션을 닫는다.

## Step 1: lesson 수집

다섯 렌즈로 세션을 훑는다:

- 사용자가 **명시적으로 교정**한 것 — "그렇게 하지 마", "이렇게 해"로 바뀐 접근 방식·규칙
- **2회 이상 반복**된 패턴 — 같은 지적, 같은 질문
- 사용자가 **긍정 확인**한 비자명한 접근 방식
- 새로 알게 된 사용자 선호·프로젝트 맥락·팀 정보
- 불편했던 워크플로우 병목·빠진 자동화

남길 lesson은 셋을 모두 만족한다: **durable**(다음 세션에도 유효) · **novel**(CLAUDE.md·coding-rules·메모리 어디에도 없음 — 대상 파일을 읽어 확인한다) · **unwritten**(코드·git·설정을 읽어 얻을 수 있는 사실이 아님). → 다섯 렌즈를 모두 훑었고, 남은 lesson마다 세 조건을 확인했다.

## Step 2: 저장소 배정

lesson마다 저장소를 하나만 고른다. → 모든 lesson이 정확히 한 행에 배정됐다.

| 저장소 | 담는 것 |
|---|---|
| `~/.claude/CLAUDE.md` (전역) | 프로젝트와 무관한 개인 선호·범용 규칙. 반영하면 페어인 `~/.codex/AGENTS.md`도 같은 내용으로 고친다 |
| `{project}/CLAUDE.md` (프로젝트) | 그 프로젝트 전용 규칙. git-tracked 공유 파일이라 반영 전에 사용자에게 확인한다 |
| 스킬 `~/.claude/skills/<이름>/` | 반복 수행한 워크플로우(Rule of Three) → 신규, 이번 세션에 스킬 동작이 불편했던 점 → 기존 스킬 수정 |
| 메모리 | user/feedback/project/reference 중 한 타입. `MEMORY.md`에서 중복·충돌을 먼저 확인한다 |
| 설계 원칙 | SW 설계 논의·결정이 있었으면 `~/.claude/skills/session-review/design-log.md`를 Read하고 그 분류를 적용한다. `coding-rules*.md`에는 그 분류를 거쳐 사용자와 합의된 문구만 들어간다 |
| `~/.claude/settings.json` (hooks·권한·env) | 매번 손으로 하던 반복 작업을 훅·권한으로 자동화할 여지 |

## Step 3: 제안 목록

**하나의 목록**으로 한 번만 묻는다(카테고리별로 나눠 묻지 않는다). 번호는 섹션을 가로질러 이어진다. → 목록을 보여주고 사용자의 선택을 받았다.

```
## 이번 세션 개선사항 제안

### CLAUDE.md
1. [전역/프로젝트] 내용 요약 — 근거: 세션에서 X 때문에

### 스킬
2. [신규/수정/삭제] 스킬명 — 내용 요약

### 메모리
3. [user/feedback/project/reference] 내용 요약

### 설계 원칙
4. [A coding-rules / B 메모리·coding-rules-<스택>] 내용 — 게이트 분류 결과

### 기타
5. 내용 요약

---
반영할 항목 번호를 알려주세요 (예: 1,3,4 / 전부 / 없음)
```

남은 lesson이 없으면 `이번 세션에서 반영할 개선사항이 없습니다.` 한 줄이 이 실행의 마지막 출력이다.

## Step 4: 승인분 반영

사용자가 선택한 항목만 반영한다 — 선택을 받기 전에는 어떤 파일도 쓰지 않는다. 항목마다 반영 직후 `[완료] {항목번호}. {내용}` 한 줄로 알린다. → 선택된 항목이 전부 반영되고 각각 `[완료]` 줄이 나갔다.

규칙 파일(CLAUDE.md·`coding-rules*.md`·메모리)에 규칙을 더했으면 마지막 `[완료]` 뒤에 `/hygiene(위생 검사)로 축적된 규칙을 정리할 때가 됐습니다.` 한 줄을 덧붙인다.

## Step 5: 종료

여러 단계에 걸친 작업이었으면 다음 세션용 프롬프트를 먼저 내고, 그다음 `세션 정리 완료. /exit로 종료해주세요.` 한 줄을 이 세션의 마지막 출력으로 낸다. → 그 줄 뒤로 아무 출력도 붙지 않았다.
