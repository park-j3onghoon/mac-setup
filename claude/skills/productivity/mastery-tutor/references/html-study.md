# HTML 공부방

학습 요청은 기본적으로 로컬 HTML 한 화면에서 이어간다. 사용자가 대화에서 풀기를 원하면 기존 대화 방식을 따른다. 스킬 자체를 고쳐 달라는 요청에는 학습 회차를 만들지 않는다.

## 호출

기록 조회·초기 지도·문제 준비는 SKILL.md와 learning-records.md의 절차를 따른다. 학습을 HTML로 넘길 때는 공용 저장소에 체크포인트를 먼저 저장한다. 이미 있는 다른 회차들은 읽기만 한다.

```sh
python3 ~/.claude/skills/mastery-tutor/scripts/study_server.py start
python3 ~/.claude/skills/mastery-tutor/scripts/study_server.py status
```

`start`가 반환한 주소에 `#회차-id`를 붙이면 그 공부가 바로 선택된다. 주소를 사용자에게 제공하며 앱 활성화·포커스 전환은 하지 않는다. 기존 서버가 있으면 재사용한다. `--root` 또는 `MASTERY_TUTOR_HOME`이 지정되면 같은 저장소를 사용한다. 기본 포트는 8766이며 충돌할 때 `--port 0`으로 빈 포트를 고를 수 있다.

화면 원본은 `assets/study.html`, `assets/study.css`, `assets/study.js`, `assets/study_markdown.js`, `assets/study_images.js`다. 실행 시 `assets/vendor/`의 고정 버전 라이브러리와 CSS·JavaScript를 합친 HTML 하나를 `{학습 저장소}/web/index.html`에 만든다. 기록 읽기·저장·채점에는 로컬 실행기가 필요하므로 반환된 HTTP 주소로 접속한다. 외부 호스팅이나 공개 배포를 하지 않는다.

## 화면과 진행

- 대화는 최신 요청·답변 한 쌍만 기본으로 표시한다. `1개 불러오기`는 이전 요청·답변 한 쌍만, `전부 불러오기`는 남은 전체 이력을 명시적으로 불러온다. `최신 대화만 보기`로 다시 접는다. 불러온 기록은 상태 조회 중 유지하고 공부를 바꾸면 최신 한 쌍부터 시작한다. 숨긴 대화에 연결된 현재 문제의 재시도 기능은 유지한다. 응답 칸은 900px 또는 화면 높이의 85% 중 더 큰 높이까지 길게 펼쳐 읽도록 한다.
- 제출한 답에는 `답변 취소하기`를 제공한다. 최근 제출 뒤 후속 학습·다른 기록 변경이 없을 때만 제출 전 체크포인트로 돌아간다. 채점 중이면 실행을 중단하고 늦게 도착한 결과를 저장하지 않는다. 완료 직후에도 같은 조건이면 취소할 수 있다. 원답·이미지는 초안으로 복구해 수정·재제출하며, 원래 요청·학습 이력·취소 이력은 보존한다. 여러 답을 함께 보낸 요청은 묶음 전체를 취소한다고 표시한다. 재시도 계보 사이에 다른 학습이 진행됐으면 이전 상태 전체를 되돌리지 않는다.
- 답안과 일반 입력에 스크린샷 붙여넣기 또는 `이미지 첨부`를 지원한다. 전송 전 미리보기·삭제가 가능하고, 이미지만 제출할 수도 있다. 한 요청에 PNG·JPEG·WebP 최대 3개, 이미지당 6MB이며 파일은 로컬 요청 폴더에 보존한다. 조회는 공부방 토큰 인증을 거친다. 선택한 Codex에는 `--image`, Claude에는 `stream-json`의 실제 이미지 콘텐츠를 전달하고, 아직 채점하지 않은 이미지 근거도 함께 제공한다. 이미지 내용도 학습 자료로만 취급한다.
- 처리 상태와 AI 응답은 보낸 자리에서 확인한다. 문제의 답을 보냈으면 해당 문제 바로 아래, `AI에게 보내기`에서 보냈으면 그 입력칸 바로 아래에 같은 응답 영역을 배치한다. 여러 답을 함께 보냈으면 마지막 관련 문제 아래에 둔다. 답했던 문제가 다음 묶음으로 넘어갔으면 문제 영역 끝에서 원답·응답을 계속 볼 수 있다. 상단에 같은 응답을 중복 배치하거나 새 응답 때문에 페이지를 위로 이동시키지 않는다.
- 설명은 로컬에 포함한 Marked·DOMPurify로 Markdown 표·제목·목록·인용·코드 블록을 표시한다. 제출한 원답은 문법을 변환하지 않고 그대로 보인다. 원시 HTML은 글자로 표시하고 실행하지 않는다. 브라우저에서 외부 라이브러리를 다운로드하지 않는다.
- 필요한 그림은 `html-diagram height=320` 코드 블록으로 전달한다. 높이는 160~720px, 기본 320px이다. 정적 HTML·인라인 CSS·SVG와 읽기 쉬운 한글을 사용한다. 블록이 닫힌 뒤 정화하여 빈 `sandbox`의 iframe에 표시한다. 그림 안의 스크립트·폼·외부 리소스·탐색은 허용하지 않으며 학습 페이지·학습 데이터에 접근할 수 없다. 일반 `html` 블록은 코드로 표시한다.
- 답안과 `AI에게 보내기` 입력칸의 Enter는 줄바꿈, ⌘+Enter는 그 입력칸의 내용만 보낸다. 문항에서는 해당 답만 제출한다. 버튼·단축키 안내는 AI 이름을 고정하지 않고 `답변하기`로 표시하며, 전송 시 선택한 Codex·Claude를 사용한다. 한글 조합 중 Enter와 키를 길게 누른 반복 이벤트는 제출하지 않는다. 빈 답·중복 요청 방지도 버튼과 동일하게 적용한다.
- 배경은 밝은 크림색, 강조는 민트·살구·연보라색을 쓰고 본문은 짙게 유지한다. 문제 옆 경과 시간과 마지막 실제 수신 시간은 위아래 두 줄로 배치한다.
- Codex는 모든 실행에 `--model gpt-6.1-sol -c model_reasoning_effort="xhigh" -c service_tier="default"`를 고정한다. `--ignore-user-config`와 함께 사용하므로 전역 fast·모델 설정에 의존하지 않는다. 자동·수동 재시도도 같은 실행 명령을 거치며 실패 시 다른 모델로 자동 대체하지 않는다. [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference).

- 왼쪽에서 저장된 공부를 고르고 오른쪽에서 전체·블록·개념별 검증 진척과 현재 공개 문제를 본다. 저장된 분자·분모가 없으면 추정하지 않고 미확인으로 표시한다.
- 상단 화면 설정에서 공부 목록과 학습 지도를 각각 접고 펼친다. 본문 기본 글자는 22px이며, 글자 크기 슬라이더와 −·+ 버튼으로 18~36px 사이에서 조절한다. 설명·문제·입력칸·주변 안내도 함께 커진다. 설정은 브라우저에 저장하고 학습 기록과 작성 중 답안은 바꾸지 않는다.
- 답안 초안은 브라우저에, 제출한 원답은 공용 체크포인트와 요청 기록에 저장한다. 정답·rubric·미공개 문제는 브라우저 응답에서 제외한다.
- 대화의 사용자 메시지에 `답안 N개 제출`만 쓰지 않고 문제 번호와 제출한 답안 원문을 표시한다. 문제를 교체하거나 다음 묶음으로 넘어가도 원답을 읽을 수 있게 요청 기록에 함께 보존한다. 이전 요청은 현재 묶음·문항 이력의 같은 ID에서 원답을 찾아 표시하며 없는 답은 만들지 않는다.
- 각 미응답 질문의 `답변하기`로 그 답만 제출한다. 다른 질문의 초안은 그대로 두며, 여러 답을 함께 보낼 때는 `작성한 답 모두 보내기`를 쓴다. 답 하나를 받을 때마다 공개 미응답 질문과 미공개 큐를 즉시 검토하고, 필요한 수정·제거를 저장한 뒤 화면에 반영한다. 채점 주기 때문에 질문 조정을 미루지 않는다.
- 공개 질문 수정은 원문을 철회하고 새 ID로 교체한다. 철회 이유와 원문은 기록에 보존하고 화면의 답변 대기에서 뺀다. 새 문항에 이전 초안을 자동으로 붙이지 않으며 무관한 질문의 초안·제출 답은 보존한다. 상세 변경 규칙은 SKILL.md의 질문 큐 절을 따른다.
- 답 보내기 또는 `이어서 공부하기`는 선택한 회차만 HTML 진행으로 넘기는 사용자 행위다. 서버는 `web:study` holder로 그 회차를 저장한다. 목록을 열거나 선택하는 것만으로 holder·진행·답을 바꾸지 않는다.
- 화면의 `보낼 AI`에서 Codex 또는 Claude를 선택한다. 답 제출·질문·이어하기·재시도는 선택한 CLI로 보내며, 기존 로그인 계정의 사용량을 사용한다. API 키를 HTML에 넣지 않는다. Codex는 읽기 전용·일회성, Claude는 `--safe-mode`와 빈 도구 목록으로 실행한다. 둘 다 외부 MCP 연결을 로드하지 않는다.
- 입력 수신과 응답 진행은 서버 이벤트로 화면에 반영한다. Claude의 구조화 출력 스트림은 공개 `reply`만 점진적으로 표시하고, Codex는 메시지 이벤트가 도착하면 공개 `reply`를 표시한다. 내부 추론·원본 체크포인트·정답·rubric을 스트림에 보내지 않는다. 저장 전 답변은 처리 중 상태로 표시하고, 검증·저장을 마친 뒤 진척과 다음 문제를 갱신한다.
- 서버 이벤트와 함께 2초 간격으로 상태를 다시 조회한다. 처리 중인 문제 옆에 상태 배지와 작은 두 줄(`43초 경과`, `마지막 수신 12초 전`)을 표시하고 큰 중복 배너는 두지 않는다. `last_activity_at`과 `activity_count`는 실행기가 실제 이벤트를 받은 때만 갱신한다. 화면 조회 성공을 AI의 새 응답으로 세거나 새 수신 없이 생성 중이라고 단정하지 않는다. 아직 수신이 없거나 수신 시점이 미확인이면 그대로 표시한다. 공개 `reply_preview`가 도착하면 해당 문제에 최근 240자를 최대 두 줄로 보여 주고 `저장 전`임을 알린다. 내부 추론·비공개 체크포인트는 보내지 않는다.
- [Codex 실행 이벤트](https://learn.chatgpt.com/docs/non-interactive-mode)와 Claude의 공개 답변 스트림을 실제 수신 단위로 반영한다. 문자 단위 전송을 보장하지 않는다. 요청 대기·응답 수신·결과 저장·자동 재시도·실패를 구분하고, 요청이 끝나도 미채점 답이 남으면 `다음 채점 대기`와 이어가는 방법을 알린다. 조회 실패는 연결 확인 필요로 표시한다. 확인되지 않은 채점 비율·남은 시간은 만들지 않으며, 상태 조회만으로 새 채점 요청을 보내지 않는다. 갱신할 때 작성 중 답안·포커스·펼쳐 읽던 과거 기록을 보존한다.
- 선택한 AI와 각 입력·응답의 실제 AI를 따로 표시한다. 선택을 바꿔도 기존 답변의 작성 AI는 바뀌지 않는다. 최근 대화와 실패한 요청은 새로고침 뒤에도 복원한다. 채점·응답 중에는 같은 공부에 중복 입력을 보내지 않는다.
- 과거 실패가 이후 재시도로 해결됐으면 `이전 시도 · 이후 재시도 완료`로 표시하고 이전 실패 응답은 접어 둔다. 실패 이력 자체를 성공으로 덮어쓰지 않는다. 재시도 연결은 `retry_of`로 기록하며, 이전 기록은 같은 문항 ID와 같은 요청 내용의 후속 성공이 확인될 때만 연결한다. 해결되지 않은 실패는 원인을 응답 맨 앞에 보여 주고 응답 안에도 `요청 재시도` 버튼을 둔다. 문제 안의 재시도 버튼도 유지한다.
- 튜터는 기록에 있는 근거로 한 턴을 처리한다. 새 원문 조사가 필요한 경우에는 부족한 근거를 알리며 자료를 지어내지 않는다. 화면에서 물어본 내용을 오답으로 처리하지 않는다.
- 실행기는 모델의 결과를 확인한 뒤 마지막 revision과 일치할 때만 저장한다. 같은 회차의 전체 체크포인트로 감싸진 응답은 내부 `state`를 꺼낸다. 원문의 `replaced_by`가 새 문항 하나를 가리키고 연결이 유일하면, 빠진 역방향 `replaces`만 복원할 수 있다. 원답·지문·정답·이력 검증은 그대로 거친다. 다른 대화가 갱신했다면 결과를 덮어쓰지 않는다. 실패한 요청의 원답과 실행 결과는 `web/jobs/{요청-id}/`에 남는다.
- 통신 오류·시간 초과·일시적인 사용량 제한·응답 형식 손상은 서버에서 5초·15초 뒤 최대 두 번 자동 재시도한다(최초 포함 총 3회). 브라우저를 열어 둘 필요는 없다. 같은 요청 ID와 저장된 원답을 재사용하고, 추가 실행 결과는 요청 폴더의 `attempt-2/`, `attempt-3/`에 보존한다. 대기 초수와 시도 횟수를 화면과 해당 문제에 표시하며 중복 제출은 막는다. 재실행 전에 revision·회차 소유권을 확인한다. 인증·결제·사용량 한도 소진, 기록 충돌·원답 변경 등 검증 실패는 자동 재시도하지 않는다. 횟수를 다 쓰거나 조치가 필요한 오류면 이유와 해당 문제 안의 `요청 재시도` 버튼을 남긴다. 여러 답을 함께 보낸 요청은 같은 요청을 한 번만 재실행한다는 안내를 붙인다. 일반 질문·이어하기처럼 연결된 공개 문제가 없는 요청만 공통 재시도 버튼을 쓴다.
- 개념 카드 갱신은 `pending_concept_card_updates`로 남긴다. 대화에서 같은 회차를 이어갈 때 최신 회차 근거로 카드를 병합한다. HTML에서 별도 카드를 저장했다고 말하지 않는다.

다른 대화에서 HTML 소유의 active 회차를 가져올 때도 learning-records.md의 소유권 확인을 따른다. 단순 기록 조회는 승인이나 넘겨받기가 필요 없다.

## 확인과 장애

`status`와 `/health`로 연결을 확인한다. 실행 로그는 `web/server.log`, 채점 로그는 요청 폴더의 `runner.log`다. 로컬 포트 열기가 샌드박스에 막히면 필요한 범위의 실행 권한으로 다시 실행한다. Chrome 검증은 등록된 공유 연결을 사용하고 `background: true`와 명시적 `pageId`를 지킨다.

서버 재시작 때 진행 중이던 요청은 실패로 표시하고 재실행하지 않는다. 채점 중 세션이 바뀌었거나 결과가 원답을 바꾼 경우에는 새 기록을 보존하고 반영을 중단한다. 실제 사용자의 답·통과 증거를 테스트 데이터로 만들거나 수정하지 않는다.
