# 완성된 스킬이 답해야 하는 네 가지

출처: `mattpocock/skills` 의 `.agents/writing-docs.md`. 그쪽은 웹사이트용 문서 페이지의 섹션 규격이지만,
우리는 별도 문서 페이지를 두지 않으므로 `SKILL.md` 만 읽고 이 넷에 답할 수 있는지를 완성 기준으로 쓴다.

## What it does

한두 문단. 한 문장짜리 역할을 먼저 쓰고, 이어서 defining constraint를 쓴다. 그 스킬이 뻔한 기본 동작과
달라지게 만드는 단 하나의 사실이다(예: `to-spec` 은 사용자를 다시 인터뷰하지 않고 이미 나온 것을 종합한다).
평서문으로 쓴다. "핵심은:" "정의적 제약:" 같은 라벨을 붙이면 그 자체가 군더더기가 된다. 이 한 줄이 가장 값지다.

## When to reach for it

두 박자로 쓴다.

- 호출 방식: 사람이 치는가, 에이전트가 스스로 부르는가. 우리는 전부 전자다("`/이름` 을 직접 친다").
- 트리거 경계: "이럴 때 손이 간다". 헷갈리는 형제가 있으면 반대편도 적는다("수정까지 원하면 `/review`").

## Common questions

실제로 나온 질문만 쓴다. 없으면 섹션을 비운다. 지어낸 질문으로 개수를 맞추지 않는다.
빈약한 스킬은 하나나 둘, 말이 많았던 스킬은 여섯까지도 된다. 자주 나온 순서로 놓고,
불편한 진실도 적는다(예: 인터뷰가 너무 길어졌다면 대개 스코프가 컸던 것이다).

## It's working if

잘 돌았을 때 눈에 보이는 것을 적는다. 우리 스킬은 단계마다 `→ 완료:` 기준이 있으므로
그 기준들이 이 역할을 겸한다. 마지막 단계의 완료 기준이 곧 "이러면 성공"이어야 한다.
